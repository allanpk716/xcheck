# xcheck 单停点全自动链 设计文档

> **文档性质**:v0.12.0——命令面 5 → 2(/xcheck、/xcheck-setup),close 四关卡并为停点一问,进度只认盘。吸收并取代 v0.9.0 的 /xcheck-close 独立闭环。
> **日期**:2026-09-16(与 grilling 会话共识一致;决策记录见 `docs/adr/0001-single-gate-autochain.md`,术语见仓库根 `CONTEXT.md`)

---

## 0. 一句话定位

`/xcheck` 一次触发,自动跑完**盲评 → 三分类 → 查证① → 实验②**,终点交付**已验证三分类清单**,停点一问("要不要起草修订并自动复审?");人的控制权在对结果的拍板上,不在过程签字上。进度只认盘(`PROGRESS.md`),恢复与排障不依赖任何会话记忆。

---

## 1. 已敲定的设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 交付物 | **已验证三分类清单**:①带 ✅/❌/❓ 判定+证据、②带实验结果、③原样带 ⚠️;必改项 = ①✅+②成立 | 用户要的"最终拿到的信息":明确的、验证完的三分类 |
| 交互面 | **全程至多 3 个开口**:弹窗0(未完成链,罕见)、摄入确认(不自包含输入,罕见)、停点一问(每轮一次) | 典型路径只开口 1 次;旧 close 四关卡是仪式 |
| 命令面 | **删除** /xcheck-diag、/xcheck-review、/xcheck-close;路由与闭环并入 /xcheck;保留 /xcheck-setup | 用户只用 /xcheck + 偶发 setup;一半表面积闲置 |
| 停点问题 | 单问:"要起草修订版并自动复审吗?" 要→自动修订+复审+同问(≤2 轮);不要→结束 | "要不要修"是对清单的天然回应;控制权留在采纳决策 |
| 摄入确认 | **保留**(仅不自包含输入触发) | 输入校验而非仪式:proposal 固化错 → 整条自动链白跑 |
| 汇总形态 | 紧凑头(各家裁决一览 + 一两句总判),共识/分歧长文取消 | 纯清单会丢"3 家反对 vs 1 家挑刺"的强度信号;长文没人细读 |
| 实验②执行 | **自动全跑**,沙箱铁律不变(临时文件落 exp/、禁改业务代码/联网/部署);单条超时(默认 300s)→"无定论";无总预算 | 危险面已被沙箱锁死;逐条勾选防的是成本不是安全 |
| 未完成链处理 | **自动发现、人工确认**("续旧的还是开新的?")——机器发现、人决定 | 用户明确要求:不自动猜,万一出问题呢 |
| 进度载体 | **PROGRESS.md**(阶段粒度,取代 run.md;字段并入) | 进度只认盘;阶段级可推理、可排障 |
| 恢复粒度 | 阶段级:已完成跳过、未完成重做整段;用户批准不跨恢复记忆 | 沿用 close-loop 已验证的粒度 |
| 复审触发 | 停点答"要"即自动接续,不再每轮另问 | 自动推进;2 轮硬上限兜底 |
| 选集来源 | `--agents` > `default_agents` > **报错停住**("先 /xcheck-setup default");缺装用交集+注明,不弹窗;同构只标注 | 分支 A 多选 UI + 表单纪律删除:罕见路径走报错 |
| diag | 维持现状(止步汇总+三分类),无验证链、无停点问题、无修订 | 不投入;diag 闭环永不做 |
| 收敛判据 | 本轮三分类①+②为空(复审轮);首轮为空 → 终态"无需修订" | 沿用 v0.9 语义 |
| 修订纪律 | 主会话亲写;新文件 `<原名>.rev<m>.md`(inline 时 `.xcheck/<ts>/proposal.rev<m>.md`);原稿不动;自代入陷阱纪律 | 沿用 v0.9 |
| 未决条目 | ❓/无定论 原样呈现在清单里,**不逐条弹窗拍板**;用户答"不要"即整体不修 | 逐条拍板是被砍的仪式之一 |

## 2. 总体数据流

```
/xcheck <内容> 或 裸敲
  │
  ├─[弹窗0 · 仅盘上有未完成链]  自动发现(扫 PROGRESS.md 无终态,取最新)
  │    问:"续旧的还是开新的?"  续 → flow 恢复模式;新开 → 继续
  │    裸敲+新开 → 反问评审内容
  │
  ├─ 路由(自动):问题→diag / 方案→review / 分不清→反问(指代词例外保留)
  │
  ├─ diag ──→ 摄入? → 冒烟 → 派发 → 收齐 → 汇总 → 三分类 → 呈现+拍板句 → 终态"完成(diag)"
  │
  └─ review ─→ 摄入?(不自包含才确认)
        → 冒烟 → 派发(默认集) → 收齐
        → 汇总(紧凑头) → 三分类 ──①+②为空──→ 交付"无可验证问题" → 终态"无需修订"
        → 查证①(只读,自动) → 实验②(沙箱,自动)
        → 【停点】已验证三分类清单 + 一问
              │不要                     │要
              ▼                         ▼
          终态"无需修订(用户决策)"     写 .rev<m>.md(原稿不动) → 建复审环(新 ts,prev 链)
          (必改项为空时不问,直接终态)      → 冒烟→派发→…→新清单
                                          ├─ ①+②为空 → 终态"收敛(N 轮修订)"
                                          └─ 第 2 轮仍非空 → 终态"推倒重来"

每阶段完成 → PROGRESS.md 打勾;终态 → PROGRESS.md 记终态
崩了/断了 → 重敲 /xcheck → 弹窗0 → 续跑(跳已完成阶段)
```

## 3. 入口(/xcheck SKILL.md 职责)

壳只做三件事,编排全在 flow.md:

1. **解析 `--agents`**(可选,规则同现状:一个空白分隔纯逗号 token;笔误报错停住列出合法名;空 token 当没敲)。
2. **未完成链检测(弹窗0)**:扫 `<cwd>/.xcheck/*/PROGRESS.md`,取**无终态记录**的最新 ts(多个未完成取最新、顺带列出其余;旧格式目录无 PROGRESS.md 不算)。存在 → AskUserQuestion 二选一:
   - `续跑 <ts>(停于:<第一个未完成阶段>)` → 设 `RESUME_TS`,转派 flow.md 恢复模式
   - `新开` → 若本次带内容,继续路由;裸敲 → 反问要评审什么
3. **路由**(逻辑照搬现状):diag/review 强信号关键词判定;单边命中直通,双边命中或双空走 ambiguous 反问;指代词例外保留。

转派时带给 flow.md:`MODE`、`OVERRIDE_AGENTS`(若有)、`RESUME_TS`(若有)。

## 4. 自动链详述(flow.md 第 0~10 步)

### 第 0 步 摄入(可选;恢复模式已勾则跳过)
照搬现状(context-intake.md 不动):不自包含输入 → 摄入确认(唯一保留的中间交互);自包含 → 零往返静默带背景。

### 第 1 步 检测 + 第 1.5 步 冒烟(照搬现状)
detect.sh;冒烟走 run-agent.sh ≤60s,坏家剔除、<2 家停。**恢复模式**:smoke 已勾则跳过,SELECTED 从 PROGRESS.selected 取。

### 第 2 步 选集(简化)
`OVERRIDE_AGENTS` > `default_agents` > **报错停住**:"未设默认集也没敲 --agents;先跑 /xcheck-setup default 设默认集"。default 有坏名(手改坏)防御剔除;缺装(∩ INSTALLED 缺员)用交集并在输出注明"默认集 X 未装,本轮用 Y",不弹窗;交集 <2 家停;同构只标注不拦。SELECTED 落 PROGRESS。

### 第 3~4 步 派发 + 收齐(照搬现状)
两层分离、run-agent.sh 全托管、搬运工铁律、raw.out/summary.md 落盘、run.md **不再写**(PROGRESS.md 取代)。

### 第 5 步 汇总(改:紧凑头)
读所有 `.summary.md`,按重写后的 `prompts/synthesize-review.md` 产出并写盘 SUMMARY.md 头部:各家裁决一览一行 + 总判一两句 + 返回家数/失败标注(+同构标注,若有)。

### 第 6 步 三分类(照搬 triage.md,写盘)
拆条标来源、三类归档、兜底往更不可信。①+②为空 → 跳 7/8,交付"无可验证问题",终态"无需修订"(不问停点问题)。diag 模式止于本步:呈现 SUMMARY + 拍板句,终态"完成(diag)"。

### 第 7 步 查证①(自动,只读)
主会话逐条查(判据直指文件,不展开探索;>10 条可分批 subagent 回传证据、主会话裁决)。三值:✅ 证实 / ❌ 证伪 / ❓ 查无实据,各附一行证据。结果并入 SUMMARY ①表格的"判定/证据"列。

### 第 8 步 实验②(自动,沙箱)
逐条执行其【方法】:临时文件一律落 `.xcheck/<ts>/exp/` 留底;**禁改业务代码、禁联网、禁部署**;单条超时(默认 300s,超时判"无定论")。三值:成立 / 不成立 / 无定论(失败/超时/环境不满足,记原因,不阻塞其他条)。结果并入 SUMMARY ②表格。

### 第 9 步 交付 + 停点
组装 SUMMARY.md 终态(格式见 §6),**呈现给用户**,然后:
- 必改项(①✅+②成立)为空 → 不问,终态"无需修订"。
- 否则 AskUserQuestion 一问:"**要起草修订版并自动复审吗?**" 选项:`要——针对必改项写修订版(新文件,原稿不动),自动重跑一轮评审` / `不要——到此结束`。

### 第 10 步 修订 + 复审(停点答"要")
1. 主会话亲写修订版:source 是文件路径 → 原文件同目录 `<原名>.rev<m>.md`;inline → `.xcheck/<ts>/proposal.rev<m>.md`。原稿不动;遵守自代入陷阱纪律;diff(原稿 vs 修订版)写入对话。原稿被手改过 → 以当前文件为基线,rev 序号顺延。
2. 建复审环:新 ts 目录 + 新 PROGRESS.md(`prev = <旧 ts>`、`round = m`、`source = <rev 文件>`),当前环 gate 打勾。
3. 自动复审 = 从第 1.5 步重跑(选集 = PROGRESS.selected ∩ 当前 INSTALLED,--agents 盖过;缺员注明)→ … → 第 9 步新清单。
4. 新一轮①+②为空 → 终态"收敛(m 轮修订)";非空且 m<2 → 同问再一轮;m=2 仍非空 → 停,报"**建议推倒重来**:两轮修订后仍存在 N 个可验证问题,疑方案根基缺陷",终态"推倒重来"。

### 收尾(任一终态)
PROGRESS.md 记终态;向用户呈现:清单、修订版路径(若有)、终态。原样输出收尾句:"**以上是建议,共识 ≠ 正确,最终你拍板。**"

## 5. PROGRESS.md(取代 run.md)

```markdown
# PROGRESS · 20260916-143012
mode = review
selected = codex, kimi
source = C:/WorkSpace/myapp/docs/api-rate-limit-design.md   # 文件绝对路径 | inline
round = 0          # 修订轮次,复审环从 1 起
prev = -           # 复审链上一环 ts;首轮 -

## 阶段(完成即打勾)
- [x] intake       # 跳过摄入也算完成
- [x] detect
- [x] smoke
- [x] fanout
- [x] collect
- [x] synthesize
- [x] triage
- [ ] verify
- [ ] experiments
- [ ] deliverable
- [ ] gate         # 打勾时机:停点已答且(答"不要"已终态 | 答"要"修订落盘+复审环已建)

## 终态
(空 | 收敛(N 轮修订) | 推倒重来 | 无需修订 | 用户中止 | 完成(diag))
```

**恢复规则**:flow.md 恢复模式读 PROGRESS 阶段勾,跳过已完成,从第一个未完成阶段起整段重做;用户已答的不跨恢复记忆(停点重问)。旧格式产物(有 run.md 无 PROGRESS.md)视为不可续跑的已完成运行。诊断/排障 = 直接读此文件。

## 6. SUMMARY.md 最终形态(交付物)

```markdown
# xcheck 评审报告 · <来源文件名或 inline>
各家裁决:codex=SUGGEST_CHANGES · kimi=AGREE(本轮 N 家返回,M 家失败:xxx)
总判:<一两句>[ ⚠️ 本次为同构,异构价值未体现]

## ① 可直接证实(N 条)
| # | 反馈[来源] | 判定 | 证据 |
|---|---|---|---|
| 1 | [codex] … | ✅ 证实 | src/foo.ts:42 |

## ② 可实验验证(N 条)
| # | 反馈[来源] | 实验 | 结果 |
|---|---|---|---|
| 5 | [codex] … | exp/e1-x.js:… | ✅ 成立 |

## ③ 存疑(N 条,仅参考)
- [codex] ⚠️ …未必准确,仅作参考

## 必改项 = ①✅ + ②成立:#1、#5(空则"无")
```

## 7. 边界与异常

| 异常 | 处理 |
|---|---|
| 某家超时/失败 | 照旧落 failed.md,清单基于其余家,头部注明 |
| 冒烟后 <2 家 | 停(话术同现状) |
| 实验①+②全空 | 交付"无可验证问题",终态"无需修订",不问 |
| 实验失败/超时 | 该条"无定论",不阻塞 |
| 停点处用户中止(不答/打断) | PROGRESS 停在 gate,终态空 → 下次可续(重问) |
| 修订写一半崩 | 旧环 gate 未勾 → 恢复时重问停点;rev 文件已存在 → 提示续用/重写 |
| 复审环 selected 有 agent 已卸载 | 用交集+注明,不弹窗;--agents 盖过 |
| 旧版 .xcheck 产物 | 无 PROGRESS.md → 不算未完成,静默忽略 |

## 9. 测试方式

1. **静态**:grep 校验结构(flow.md 标题序、PROGRESS 关键词、无 close-flow 残留引用);`xcheck/tests/run-agent.test.sh` 全绿。
2. **端到端(用户,开新会话)**:
   - `/xcheck <设计文档路径>` → 全链自动推进到停点,全程仅一问;答"要" → rev1 落盘原稿不动 → 自动复审 → 收敛/推倒重来。
   - 中途 Ctrl 打断 → 重敲 `/xcheck` → 弹窗0 → 续跑跳过已完成阶段。
   - 裸敲无未完成 → 反问内容;`/xcheck <报错栈>` → diag 路径止于三分类。
   - 故意不设 default_agents(临时清掉)→ 报错提示 /xcheck-setup default。
