# xcheck 评审链耗时优化方案（rev1）

> v1 固化稿经 codex+pi 盲评（20260917-151728，2/2 SUGGEST_CHANGES）+ 查证 10 条证实 + 实验 1 条成立后修订。原稿 `2026-09-17-xcheck-perf-consensus.md` 不动。相对 v1 的关键变化：① 主杠杆从「只压 codex」改为「按最慢通道（max 口径）多通道降耗」；② codex 经本地代理调推理档已被实验证伪，A 改为先验证后固化；③ 砍掉 poll 改档（收益可忽略）；④ 补齐闸门搬迁、验收标准、回滚条件、数字口径；⑤ 全局配置改动统一降级为低风险+备份。

## 1. 问题

用户体感：每次评审，等待时间很长。**优化目标口径 = 链路墙钟（并行派发下 ≈ 最慢通道的耗时）**，不是单通道耗时，也不是 token 消耗（token 只作成本参考）。

## 2. 实测基线（2026-09-17，来源：三个项目 .xcheck/ 运行日志 + 本轮）

数字口径统一如下，后文全部按此引用：

| 口径 | 数值 |
|---|---|
| 冒烟地板（单通道，读一行回显） | codex 45s · pi 30s · kimi 30s |
| 冒烟串行总耗 | 默认集（codex+pi）75s · 三通道 105s |
| 冒烟并行化后 wall | max ≈ 45s（两口径同） |
| 评审实跑（读 1 个方案文件+出结论） | codex 2m01s~3m17s（本轮 2m01s）· pi 2m16s~5m02s（本轮 3m01s）· kimi 1m~4m |
| 链路 wall 实录（=max 通道） | 2m32(codex 瓶颈) / 3m17(codex) / 5m02(pi) / 3m01(pi) |
| codex 单轮评审 token | 18,879（输入仅一个 ~4KB 方案文件） |

关键事实：**四轮里两轮瓶颈是 pi、两轮是 codex**；pi 峰值 5m02s 是全链最高。只优化单通道，链路 wall 下限仍被另一通道抬住。

## 3. 根因（按 max-通道口径重排）

1. **两个默认通道都是重型模型配置**：codex 走本地代理 → glm-5.3（model_reasoning_effort="high"）；pi 走 ccswitch → claude-opus-4-8。任何一家慢，整链就慢。
2. **冒烟串行 + 每轮重跑**（固定开销，见上表）。
3. **轮次乘数**：收敛 N 轮 = 全链 ×(1+N)。
4. 小额固定开销（死 MCP 重试秒级、hooks 秒级；poll 粒度经核算收益可忽略，见 §4-C'）。

## 4. 优化项（修订后）

### A'. 多通道降耗 —— 先实验验证，后固化配置（替代 v1-A）

v1-A「codex per-run 降推理档」已被实验**证伪**：`-c model_reasoning_effort=medium` 在 CLI 层生效（banner 回显），但经本地代理 → glm-5.3 后 token 反增 4.2×（13,725 vs 3,236）、wall 无差异（32s vs 31s）。**推理档参数这条路在当前代理下不降耗。**

修订后的 A' 是一个验证驱动的工作流，对**每条通道**独立执行：

- **候选手段**（每通道至少考察一条）：
  - codex：(a) 绕开本地代理直连端点后重测 effort 档；(b) per-run 模型覆盖（`-c model=<更小模型>`，须先确认代理/端点支持该模型）。
  - pi：per-run 模型覆盖（ccswitch 换档；或 pi 的模型选择参数，若 CLI 支持）。
  - kimi：thinking 档配置（kimi-code 全局 config 的 thinking 相关项，属全局改动，按 E' 纪律走）。
- **三指标验证**（缺一不进配置）：同一中等任务，基线档 vs 候选档各跑 ≥2 次取中位 —— ① wall 下降 ≥30%；② token 不升；③ 输出质量不劣化（质量判据见 §5）。
- **固化**：验证全过才写进 `agents.toml` 的 run_cmd / 配置；写明这是 per-run 覆盖，不动用户全局默认。
- **结构限制（明示）**：主会话的查证环节只能核实 agent 已提出的条目，**不能补回降档后 agent 漏提的新问题**——所以任何降档必须先过 §5 质量对比，不允许"先上后看"。

### B'. 冒烟并行化 + 复审环跳过冒烟 + 闸门搬迁（细化 v1-B）

- **并行冒烟**：主会话一条消息并发后台启动各通道冒烟（沿用「后台启动 + 回合内阻塞等待」纪律，不许前台直等），wall 从串行 75s（默认集）降到 max≈45s。
- **复审环跳过冒烟**（跳过条件与兜底）：
  - 跳过条件：仅限同一链的复审环（prev 非空），且上一环该通道冒烟通过。
  - **判活闸门搬迁**：跳冒烟后，「幸存 <2 → 停」的闸门移到 collect 阶段——任何通道 exitcode∈{65,66,67,124} 或 spawn 失败即记 failed.md；collect 后幸存 <2 → 按第 1 步同款话术停链。
  - PROGRESS 记录规则：复审环的 smoke 阶段照常打勾，但注记 `smoke # 复审环跳过，判活闸门在 collect 兜底`，恢复协议以此为准，无歧义。

### C'. 砍掉 v1-C（poll 15→5s）

实测核算：平均每通道仅省 ~5s（检出延迟 7.5s→2.5s），相对 2~5m 的通道可忽略，且轮询进程创建 ×3。不做。

### D'. 增量复审 —— 降级为可选设计原则（细化 v1-D，默认不做）

v1-D 的偏收敛风险成立（聚焦验旧项 → 新问题发现率必然下降 → 更易误判收敛，与 m=2 推倒规则叠加放大）。若未来要做，必须同时满足：

- prompt（指令层）**仍要求整文重评**，并**专项要求检查修订新引入的问题**——增量材料只是附加输入，不是评审范围的收缩；
- 上轮必改项与修订 diff 走**内容层文件**（如 `prev-issues.md`），不占指令层 2KB 限制；
- 跨轮引用统一 `上轮#n` 前缀，triage 与结论区机械拼装时保留前缀不重排；
- 若某复审轮全部必改项均来自上轮同编号条目且无新发现，SUMMARY 标注「增量偏置可能：本轮无新发现」，提示人工复核后再接受收敛判定。

### E'. 全局配置改动 —— 低风险 + 备份 + 可回滚（修订 v1-E）

凡动 `~/.codex/config.toml`、`~/.pi/agent/`、`~/.kimi-code/` 等全局配置（含清理失联 MCP、hooks 复核、kimi thinking 档）：

1. 先确认归属（该配置是否还有 xcheck 之外的用途，拿不准就问用户）；
2. 改前把原值备份成带时间戳的旁路文件，并在改动记录里写明回滚命令；
3. 改后实跑冒烟验证；
4. 收益若只有秒级（如死 MCP 重试），优先级排到最后甚至不做。

与 A' 的口径统一为一条原则：**per-run 覆盖优先于全局改动；全局改动一律走备份-验证-回滚三步。**

## 5. 验收与回归（补全）

- **质量判据**（A' 的③指标）：同一真实方案，基线档 vs 候选档各完整评审一轮，对比：(a) 候选档对基线档所提问题清单的覆盖率 ≥80%（按问题实质等价判定）；(b) 候选档新增的有效问题数 ≥0（允许少，不允许漏到负贡献）。判定由主会话做，结果落 SUMMARY。
- **性能判据**：wall 与 token 双指标，取 ≥2 次中位；wall 不降或 token 反升 → 该通道候选手段否决（v1-A 即按此判死）。
- **回滚条件**：已固化进 agents.toml 的降耗配置，若后续任一链出现「该通道连续 2 轮必改项命中数显著低于历史基线」，回滚 run_cmd 并在 CHANGELOG 记录。
- **回归**：run-agent.sh 改动必跑 `bash xcheck/tests/run-agent.test.sh`（33 断言）；时序相关断言若受影响，一并修。
- **文档同步义务**：CHANGELOG / CONTEXT.md / README / AGENTS.md / docs/artifacts.md。
- **端到端验收**：改完后用一条真实评审链实测，冒烟 wall ≤60s（并行）、评审轮 wall 较本轮基线（3m01s）下降 ≥25%，且必改项命中数不明显低于本轮（10 条证实/11 条必改）。

## 6. 不做什么

- 不动「搬运工只搬运 / 单停点 / 实验沙箱」等铁律不变量。
- 不为速度牺牲异构性（≥1 非 claude）。
- 不做 poll 粒度调整（收益可忽略）。
- 不在无质量对比的情况下固化任何降档/换模型配置。
