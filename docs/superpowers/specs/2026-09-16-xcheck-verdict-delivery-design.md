# xcheck 结论人话交付 + 评审附录 — 设计

日期:2026-09-16 · 状态:已批准(经 grilling 七问 + 三轮"看不懂"打磨) · 版本:0.14.0

## 背景与痛点

用户实跑 review 模式后反馈:多 agent 评完、合并意见时"看不懂该不该推进,还是哪里不对"。四个卡点全部命中:

1. **缺一句"能不能推进"**——第 9 步只拼编号,从无状态行;第 5 步写紧凑头时查证未发生,天然给不出结论。
2. **必改项只有编号**——triage.md 输出模板没定义编号,flow 却引用 `#1、#3`;各家评的严重度在 triage 时被丢弃。
3. **各家裁决没参与决策**——AGREE/SUGGEST_CHANGES 只在第 5 步露一面。
4. **三分类明细淹没重点**——第 9 步"呈现 SUMMARY 全文"把三堆平铺。

设计过程暴露的**根因**(三轮"看不懂"定位):现有产物全在讲流程自己(三分类/停点/enum/①②③),没有一句在讲"你的方案怎么样"。工具一直在说自己,没在说用户的事。

## 核心原则

**对话说人话,文件留机器账。**

- 编号、enum、严重度标签、①②③——只出现在 `.xcheck/<ts>/SUMMARY.md`(机器账,可追溯、可 grep)。
- 对话与被评文档文末的**评审附录**用自然语言:每句话都在说用户的方案,agent 名只作为"谁提的"出现,不用裁决码。
- 过程中(第 4~8 步)用户**不欠任何操作**;全链唯一问句在第 9 步停点。每个时刻的播报当场写明"你现在欠什么"。

## 设计决定

1. **结论区(机械拼装,置顶 SUMMARY.md)**,第 9 步组装:状态行(✅ 可推进 = 必改空 / ⚠️ 先修订再推进 = 必改非空)+ 必改项全文(`#n [来源][严重度·类型] 一句话 —— 证据`)+ 各家裁决一行 + 信号行 + 统计行。**零新判断**——每字段有既定来源,裁决与必改"对不上"是留给用户的信号,系统不圆场。
2. **对话呈现 = 结论区的人话渲染**:首句结论("方案能用,但有 N 个问题已查实,建议改完再动手——改不改你定")+ 已查实必须改(逐条,谁提的+证据)+ 查过不用理(证伪逐条)+ 没法验证开发时要盯(③全部+②无定论,含**触发点**与**命中动作**)+ 明细指针 + 拍板句。不再平铺 SUMMARY 全文。
3. **编号**:①②条目全流水 `#1、#2…`(③不编号);严重度标签 `[高|中|低·bug|风险|遗漏]` 取自各家原评,丢标兜底 `[未标]`。
4. **总判三定式**(synthesize-review.md):焦点共识 / 意见分裂 / 一边倒,≤2 行,作为结论区信号行素材;DISAGREE 家数显式标注。
5. **过程播报契约**(flow.md 第 5~8 步):每步播报一两行人话 + "无需操作";明细只落盘。评审回收播报:`✓ N/M 家返回(裁决人话化),正在逐条核实,这几分钟不用你做任何事`。
6. **停点问句带数量**:"要我把这 N 个问题改了、再自动评一轮吗?"
7. **终态拆分**:必改非空但用户答"不要" → 终态 **`用户不修`**;`无需修订` 只留给 **round 0** 的 ①+② 真空/必改空;round ≥ 1 必改空 → `收敛(m 轮修订)`(修干净了,不算"无需")。终态枚举六值(含既有 `完成(diag)`,修 CONTEXT 词汇漂移)。
8. **评审附录**:链达成**结论性终态**(收敛/推倒重来/无需修订/用户不修)时,若 source 是文件路径,**先写附录、再写终态**(防窗口),在被评文档文末追加/按 ts 幂等重写一节:
   - 节首固定声明:**评审参考,以实际执行为准**(证据是评审时点快照);"撞上关注项停下反馈"是动作不是参考。
   - 内容 = 对话人话版全部区块 + 修订版路径 + 产物目录;用户选"不修"也写,标注"用户选择不修"。
   - source=inline(贴文)→ 不写,对话明说"清单留在 `.xcheck/<ts>/`,请自行关联",不假装关联。
   - 用户中止 / 完成(diag)不写附录。
9. **不设第三态**(根基存疑):DISAGREE 家数进信号行,等真实案例再议(YAGNI)。
10. **本轮只改 review 链**,diag 全链不动。

## 边界与纪律

- **原稿正文永不动**的铁律改口径:正文永不动;文末附录节是唯一例外,仅终态写、按 ts 幂等重写。
- 附录写失败(文档只读/被删)→ 跳过附录、对话注明,不阻塞终态。
- 多轮修订:每环 source 指向各自文档(rev 系列各带自己的附录),不跨文档合并。
- xcheck 管不到执行:附录把参考与"命中即报"指令递到计划文档里,守不守是开发流程的事。

## 验收(下次实跑检查单)

- [ ] 评完到停点之间,对话里没有问句、没有三堆明细平铺;每段播报带"无需操作"
- [ ] 停点前能看到一句"能不能推进"的人话结论,带必改数量与证据
- [ ] 必改项在对话里逐条可读(内容+谁提的+证据),不出现裸编号
- [ ] ③+②无定论以"开发时盯住"形式出现,每条带触发点与命中动作
- [ ] 答完停点后,被评文档文末出现评审附录,含"以实际执行为准"声明
- [ ] 答"不要"后 PROGRESS 终态 = 用户不修(而非无需修订)
