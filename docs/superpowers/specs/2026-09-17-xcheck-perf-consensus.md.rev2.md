# xcheck 评审链耗时优化方案（rev2）

> rev1 经第 2 轮盲评（20260917-153240，2/2 SUGGEST_CHANGES，15 条全数查实）后修订。相对 rev1 的变化：① collect 判活改"非 0 即败"；② 质量判据重写（高严重度全覆盖 + 删恒真指标 + 裁决/严重度不劣化 + 双样本）；③ ccswitch 移出 per-run 归入全局纪律；④ 跳冒烟条件收紧为"上一环完整成功 + agents.toml 未变更"；⑤ 端到端验收改多轮中位 + 条件式目标 + 计时边界定义；⑥ token 从硬否决降为软预算；⑦ 回滚判据给定量下限；⑧ 固化段补 run_cmd 空格约束。

## 1. 问题

用户体感：每次评审，等待时间很长。**优化目标口径 = 评审段墙钟（fanout 起 → collect 齐）**，并行派发下 ≈ 最慢通道耗时；主会话查证/实验段为串行附加段，单独计量、不在本目标内。token 是成本参考，不是目标。

## 2. 实测基线（2026-09-17，三个项目 .xcheck/ 运行日志 + 本链两轮）

| 口径 | 数值 |
|---|---|
| 冒烟地板（单通道） | codex 45s · pi 30s（偶发 61s+ 撞 60s 预算，冷启动波动） · kimi 30s |
| 冒烟串行总耗 | 默认集（codex+pi）75s · 三通道 105s |
| 冒烟并行化后 wall | max ≈ 45s |
| 评审实跑 | codex 2m01s~3m17s · pi 2m16s~5m02s · kimi 1m~4m |
| 评审段 wall 实录（=max 通道） | 2m32 / 3m17 / 5m02 / 3m01 / 2m02（本链 r1） |
| codex 单轮 token | 18,879（评审）/ 3,236~13,725（小任务，档位间无差异） |

关键事实：**五轮里瓶颈 codex 2 次、pi 3 次**；只优化单通道，评审段 wall 下限仍被另一通道抬住。

## 3. 根因（按评审段 wall 口径）

1. 两个默认通道都是重型模型配置（codex→代理→glm-5.3@high；pi→ccswitch 档→claude-opus-4-8）。
2. 冒烟串行 + 每轮重跑（固定开销见上表）。
3. 轮次乘数：收敛 N 轮 = 全链 ×(1+N)。
4. 小额固定开销（死 MCP 重试、hooks，均秒级；poll 粒度收益可忽略不做）。

## 4. 优化项

### A''. 多通道降耗 —— 先实验验证，后固化配置

v1 的 codex 推理档路径已被实验证伪（CLI 层生效、代理层不降耗：medium token 反增 4.2×、wall 无差异）。A'' 对每条通道独立执行：

- **候选手段（仅 per-run 性质）**：
  - codex：(a) 绕开本地代理直连端点后重测 effort 档；(b) per-run 模型覆盖（`-c model=<更小模型>`）。
  - pi：**仅** pi CLI 自身的模型选择参数（若 CLI 不支持，如实记录"pi 通道当前无 per-run 手段"，不硬凑）。
  - kimi：无 per-run 手段（thinking 配置在全局 config，见 E''）。
  - **ccswitch 不在此列**——它是全局档位切换器（切的是所有会话共享的 profile），不是 per-run 手段；若要走它，按 E'' 全局纪律处理，且须先做并发隔离验证（两条并行链 + 用户其它会话同时在场时无互扰）。
- **验证（wall 为硬指标，token 为软预算）**：同一中等任务，基线档 vs 候选档各跑 ≥2 次取中位——① wall 降 ≥30%（硬）；② token 中位增幅 ≤50%（软：超限不自动否决，提示用户拍板）；③ 质量不劣化（判据见 §5，硬）。
- **固化**：三指标通过才写 `agents.toml` 的 run_cmd。**固化自查**：run_cmd 按空格分词、每个 token 不得含空格（含 `=` 的值同样不能带空格）；模型覆盖参数若无法写成无空格 token，则该手段判不可固化，换路径。
- **结构限制（明示）**：主会话查证只核已有条目，**补不回降档后漏提的新问题**——所以质量判据是硬门槛，不允许"先上后看"。

### B''. 冒烟并行化 + 复审环跳过冒烟 + 闸门搬迁

- **并行冒烟**：主会话一条消息并发后台启动各通道冒烟，沿用「后台启动 + 回合内阻塞等待」纪律；wall 从串行 75s（默认集）降到 max≈45s。
- **复审环跳过冒烟**，跳过条件（三条全满足）：
  1. 同一链的复审环（prev 非空）；
  2. 上一环该通道**完整成功**：冒烟通过 **且** 实际评审运行成功（产出 `.summary.md`）——仅冒烟通过不算；
  3. 自上一环以来 `agents.toml`（含 run_cmd）**未变更**——改过配置则旧冒烟证明对新命令无效，强制重跑冒烟。
- **判活闸门（collect 阶段）**：**exitcode ≠ 0，或 spawn 失败，或产物缺失（无 .summary.md / raw.out），任一即记 failed.md**——不枚举失败码，任何非零退出（401 欠费、配额、CLI 崩溃等）一律按失败处理；collect 后幸存 <2 → 按第 1 步同款话术停链。
- **PROGRESS 记录**：复审环 smoke 阶段照常打勾并注记 `smoke # 复审环跳过（上一环完整成功+配置未变更），判活闸门在 collect`；恢复协议以此为准。

### C''. 砍掉 poll 调整（不变）

实测平均每通道仅省 ~5s，可忽略。不做。

### D''. 增量复审 —— 可选设计原则（默认不做，不变）

若未来要做：prompt 仍要求整文重评 + 专项检查修订引入的新问题；上轮必改项与 diff 走内容层文件（`prev-issues.md`），不占指令层 2KB；跨轮引用统一 `上轮#n` 前缀，拼装不重排；复审轮必改项全部来自上轮同编号且无新发现时，SUMMARY 标注「增量偏置可能」提示人工复核。

### E''. 全局配置改动 —— 低风险 + 备份 + 可回滚（含 ccswitch 路线）

凡动 `~/.codex/config.toml`、`~/.pi/agent/`、`~/.kimi-code/`、**ccswitch 档位**等全局状态：

1. 先确认归属（该配置是否还有 xcheck 之外的用途，拿不准就问用户）；
2. 改前备份原值（带时间戳旁路文件）+ 记录回滚命令；
3. 改后实跑冒烟验证；涉及档位切换的加做并发隔离验证；
4. 收益仅秒级的（死 MCP 重试等）排最后或不做。

原则统一：**per-run 覆盖优先于全局改动；全局改动一律走备份-验证-回滚三步。**

## 5. 验收与回归

- **质量判据（A'' 的③，硬门槛）**——基线档 vs 候选档，**≥2 份不同方案**（其中 1 份可为小型方案）各完整评审一轮：
  - (a) **高严重度全覆盖**：基线档提出的每条【高】问题，候选档都以实质等价形式提出（允许措辞不同，不允许漏）；
  - (b) **有效问题总量**：候选档有效问题总数 ≥ 基线档的 70%（可判的对称指标，替代 rev1 恒真的"≥0"）；
  - (c) **裁决与严重度不劣化**：最终裁决三值不变；若变化须给出可核查理由；基线档【高】条目在候选档不得无理由降级为中/低。
- **性能判据**：wall 降 ≥30%（硬，≥2 次取中位）；token 中位增幅 ≤50%（软预算，超限提示用户拍板）。
- **回滚条件（定量）**：已固化的降耗配置，若该通道**连续 3 轮**必改项命中数 **< 历史基线中位数的 50%**，回滚 run_cmd 并记 CHANGELOG；单轮波动不触发。
- **端到端验收（条件式）**：
  - 计时边界：**评审段 wall = fanout 起 → collect 齐**（不含主会话 verify/experiments 串行段；全链 wall 另行记录供参考）。
  - 若 A'' 至少一条通道固化：**≥3 条真实评审链取中位**，评审段 wall 较本链基线（r0=3m01s / r1=2m02s，取 3m01s 保守值）下降 ≥25%。
  - 若 A'' 全部候选被否决（质量/性能判据不通过）：端到端目标降为「仅 B'' 生效」——冒烟 wall ≤60s（并行）、复审环跳冒烟后每轮省 45s，并明示"A'' 无通道固化"。
- **回归**：run-agent.sh / flow.md 改动必跑 `bash xcheck/tests/run-agent.test.sh`（33 断言），时序断言受影响一并修。
- **文档同步义务**：CHANGELOG / CONTEXT.md / README / AGENTS.md / docs/artifacts.md。

## 6. 不做什么

- 不动「搬运工只搬运 / 单停点 / 实验沙箱」等铁律不变量。
- 不为速度牺牲异构性（≥1 非 claude）。
- 不做 poll 粒度调整。
- 无质量对比不固化任何降档/换模型配置。
- 不把全局档位切换（ccswitch）伪装成 per-run 手段。
