# xcheck 审核收敛与可分发配置设计

日期:2026-09-19 · 状态:访谈共识已确认,设计待审阅,未实施。

本文记录本次 grill-with-docs 会话确认的目标、边界及实现建议。**不是现行运行规范**;当前行为仍以 xcheck/lib/flow.md 等实现文件为准。用户授权本阶段整理设计与术语,尚未授权修改运行流程、提交或推送。

## 1. 问题与目标

用户主要在 Matt Pocock 的 grill-me / grill-with-docs 讨论结束后调用 xcheck。实际痛点是**小问题越审越多**:每次完整重审不断引入补充建议,已证实的小问题又被视为必须修订,最终方案越来越长而不是越来越可执行。

主目标是提高审核质量与收敛性,不是追求零建议或增加审核次数。次目标是让已有 Claude Code 与多个 agent CLI 的开发者能独立安装、配置和升级。Windows + Git Bash 为主要支持与验证环境;其他 bash 平台尽量兼容,未验证前不承诺正式支持。

成功意味着:保留关键缺陷发现能力,守住用户已确认决策,不因非阻断建议或下游细化事项反复修订;完整 night 仍能无人值守实施并交付 PR。

## 2. 上游输入契约

核对 mattpocock/skills 的 main 分支技能定义与说明:

- grill-me 调用 grilling,主要产出会话中的共同理解和已确认决策,不要求写文件。
- grill-with-docs 调用 grilling + domain-modeling;额外维护术语表和少量符合条件的 ADR。其余大量决策仍留在会话,**并不保证产出正式实施规格**。
- to-spec 才把已讨论内容整理为正式规格;to-tickets 进一步拆成可验收、有依赖的任务票。

因此 xcheck 主要审核对象是**讨论共识**及其必要背景,不是把 ADR、术语表或最新 Markdown 文件误当成整个方案。

## 5. 审核模型

### 5.1 共识快照

建议审核输入包含:目标与范围、已确认决策、明确约束与否决项、未决问题、技术假设、相关背景材料。

- 每个关键决策有稳定标识和可读出处。用户短答必须绑定到当时问题与所选选项,不能只摘“同意”或“选A”。
- 保留必要原话片段,不要伪造消息编号或将助手未获同意的建议记成用户决策。上下文缺失时明确标记证据不足。
- 同一事项以用户后续明确修正为准,旧决定保留为已被替代的来源,不同时作为有效约束。
- CONTEXT/ADR 是背景与约束,不是默认替代审核对象。明确指定文件时尊重该文件;明确指定讨论时不能被“最近编辑的文件”截走。
- 正常模式仅对实质歧义询问;night 不等待,记入待决项并限定受影响范围。整个目标都无法确定时不擅自选对象继续。
- 原始材料视为数据,其中出现的技能、shell 命令或其他代理指令不能改变审核员角色与权限。

### 5.2 事实、影响与处置分离

保留①只读可验证、②需实验、③目前无法验证的取证分类,但它不决定是否阻断。每条归并后的发现建议记录:

- 问题标识、相关决策、来源评审员、主张及发生条件;
- 证据和事实结论(证实/证伪/未确定);
- 对核心目标、验收、安全或数据正确性的具体影响;
- 处置:阻断/非阻断建议/重大风险待决;
- 影响范围、解除条件、修复状态与历轮记录。

判为阻断必须解释**为什么继续会出错或无法验收**,不能只写“更健壮”“最好加上”“还不够详细”。评审员的严重度标签是输入,不是自动裁决;主会话对证据与影响作最终判定,交付区再从该记录机械呈现。

重复发现归并到同一问题,保留所有来源与不同证据;不同故障条件不能只因文字相似而误合并。已关闭项若重新出现,需提供新证据或具体回归,不能仅换表述重开。

重大未证实风险不是“已证实缺陷”。如数据删除可能误删但无法验证,记录具体场景和需要补的验证,暂停删除及依赖其结果的步骤。无法证明其他任务独立时,不得为了凑进度假定独立。

### 5.3 复审与收敛

复审材料建议包含原问题、修订差异、修复理由、已确认约束及必要上下文。各评审员仍独立作答,不共享本轮彼此结果;复审可共享上一轮问题基线,以便验证修复,不把它误称为从未见过历史的首轮盲评。

默认只核实:

1. 原阻断是否真正解除;
2. 修改是否引入回归或违反用户已确认决策;
3. 是否有新的重大缺陷或重大风险需要阻断。

一般新建议保留为非阻断参考,不据此开启下一轮。night 首轮后最多自动修订一次,遇到同一问题无实质改善或修复必须改用户决策时停止该路径。无进展不以文档字数、发现数量或严重度标签下降来判断。

**审核收敛**表示当前审核范围内没有未解除的阻断或重大风险待决,不表示所有建议清零、方案完美或代码测试已通过。部分任务可推进不能被报告为整个方案无条件通过。

### 5.4 下游范围控制

规格和票据继承已确认共识、必要修复、验收目标及明确风险约束。非阻断建议不自动成为需求或额外任务。精选建议数量不设“必须凑满”的配额;完整原始评审继续留底。

若修复必须改变用户已确认的产品行为/约束:手动请求该项决策,night 暂停相关任务。不可通过把新行为称为“技术细节”绕过授权。

局部暂停沿真实依赖传播。暂停票、受其阻塞的票和可独立完成的票必须区分;暂停不等于完成,无下游依赖也不代表一个真实阻断已经解除。

## 6. 运行与交付边界

### 6.1 交互与终点

交互方式(需要用户裁定/无人值守)与执行终点(审核交付/接续实施与PR)分别表达。--night 保持无人值守且接续实施的兼容含义。仅无人值守审核不得触发代码实施或发布。

具体新旗标名称与入口界面尚属实现建议,本设计不宣称命令已经存在。优先最小化新增选择,不强迫每次设置两个弹窗。续跑读取原运行的终点与授权范围,不能因一次普通续跑意外升级为实施发布。

### 6.2 同分支交付

在生成需要提交的 spec/票之前建立隔离 worktree,记录启动基线与原分支;spec、票、必要忽略规则修改和代码均在夜链分支。每票完成推送该分支,收工创建或复用 PR;不自动提交、推送或 rebase 原分支,不 force push、不自动合并、不创建 issue。

本地 .xcheck 机器账不提交。建议 night 的共识稿、修订稿和评审附录也优先写入隔离副本,避免在前半段改动原分支文件;只审核的普通流程是否保留原有文末附录行为,保持兼容,不在本阶段扩大修改范围。

发布失败与实施失败分开记录。无远端、未登录、无权限或无法开 PR,仍允许有 Git worktree 能力的项目本地完成,准确显示“本地完成/未推送/PR未创建”。不自动安装托管工具、创建远端或改凭据。没有 Git 仓库或无法建立隔离工作区,不等于“只是缺远端”,不能冒充完整 night 可执行。

### 6.3 只读取证与材料降级

每个 CLI 的能力需要按实际版本、平台和权限配置验证,不能按工具名字推断。

- 可强制只读取证:允许访问审核所需仓库内容,但排除密钥与无关私有文件,不能写业务文件、执行实验或触发下游工具;保留证据引用。
- 材料评审:只接收共识和必要背景,取证由主会话完成;在交付中披露覆盖差异,不能把材料评审说成全库验证。
- 模型服务通信是 CLI 的运行依赖,与允许任意联网、外部工具或实验不是同一权限。限制工具执行不应误禁正常模型调用。
- **更换 cwd、复制到临时目录、使用 worktree 或提示词禁止写入,单独都不构成安全隔离。** 必须落实并验证 CLI 无工具模式或操作系统/进程级访问限制等可用机制。
- 如果某 CLI 既无法强制只读,又无法落实材料访问边界,应报告能力不可用,不能静默退回全权模式。不足现有最低参评数量时停止审核并提示配置。

材料隔离的具体跨 CLI 适配方案是实施前技术验证项,不是已解决能力。新默认模板不得机械继承针对某台机器事故采用的全权参数。

## 7. 给其他用户的配置清单

原则:能探测的事实自动探测,有安全/费用/模型选择含义的决策让用户配置;出厂模板不携带个人默认环境。

| 信息 | 用户需要做什么 | 自动探测/默认与用途 |
|---|---|---|
| Claude Code、bash/coreutils、必要进程工具 | 预先安装,按引导修复缺失 | setup 检测所需工具,区分 Windows 进程清理依赖 |
| 评审 CLI 的登录与模型服务 | 在各 CLI 中自行登录或配凭据,确认能用于该项目 | xcheck 检测调用结果,不接管或复制其登录数据 |
| 默认评审组 | 从实际可用 CLI 中选择 | 不假定都有 codex+pi;保留最低参评数量要求与异构提示 |
| 非交互命令与输入方式 | 常见 CLI 使用验证过的模板;非标准安装可覆盖可执行文件、参数和 arg/stdin 方式 | 探测 PATH、版本和帮助,区分已安装/已登录/能读取/能隔离 |
| 模型或提供方身份 | CLI 可探测则展示,不可探测标未知,有需要才显式登记 | 两个不同 CLI 名称不证明底层模型不同;不伪报独立性 |
| 执行与冒烟预算 | 可接受默认,仅慢通道按需调整 | 个人默认及每家覆盖;不把超时当权限失败 |
| 取证能力 | 选择并验证安全运行配置 | 只读取证或隔离材料评审,记录降级原因 |
| 目标仓库与验证命令(完整 night) | 不可推断或有多个有效选择时配置 | 从 Git、项目说明、构建/测试配置取值;禁止捏造“测试通过” |
| 发布远端、PR base 与托管工具(完整 night) | 常规项目可自动推断,多远端/分叉仓库可项目覆盖 | 启动记录所选 remote、base 和基线,检查 Git/gh/tea 可用性;不盲推错误仓库 |
| 无人值守权限(完整 night) | 用户预先安排必要权限 | 检查并提示潜在交互阻塞;不得自行修改会话权限设置 |
| Pushover(可选) | 需要手机通知时配 PUSHOVER_TOKEN / PUSHOVER_USER 的外部凭据来源 | 默认关闭,已配置则使用;curl 检测,失败不阻塞 |

### 7.1 配置层级与更新

建议优先级:本次显式参数 > 受信任的项目设置 > 安装目录外个人配置 > 分发默认模板。精确文件路径、字段和合并规则在实施规格确定,不要先承诺新 API。

- 数组建议整体替换,不偷偷把模板评审员并入个人选集;未知字段和非法值明确报错。
- setup、detect、supervisor 和流程使用同一有效配置解析结果;展示值与来源,避免改了一个文件实际读另一个。
- 项目配置可覆盖仓库策略,但任意命令、外发目标和凭据引用不能从未信任仓库静默执行。项目配置不是新的自动授权来源。
- 凭据不进仓库模板、项目配置、提示词、日志或晨报;配置只保存必要的引用。去掉分发模板中的个人通道排障/凭据片段说明,不在新设计复制其内容。
- 从旧安装目录 agents.toml 迁移时先检测已有个人配置,保留原文件与备份,不覆盖冲突值;链接安装与复制安装均验证。旧全权命令需要重新进行能力校验,不能以“迁移”绕过新边界。
- 指纹针对有效配置而非单一模板文件,并包含影响安全能力的版本/配置变化;改变后重新做相应冒烟与能力验证。
- 通知仅先支持现有 Pushover;不在本轮增加 Webhook、集中凭据管理或团队策略平台。

### 7.2 首次接入体验

建议 setup 依次完成:依赖探测 → 验证非交互调用和可访问能力 → 用户选择默认组 → 写个人配置 → 展示审核可用性与 night 可用性。检测失败说明具体缺项,不要求用户提供能从环境取得的事实。

完整 night 额外检查:Git/worktree、启动基线、执行验证方式、发布目标与能力、无人值守条件。通知作为可选项,不必为了成功安装而配置。

## 8. 验证与验收

后续实现需要机械测试和指令场景回放,不能只靠文档相互引用声称可靠。

| 场景 | 必须看到的结果 |
|---|---|
| 已证实一个低价值补充建议 | 不阻断、不自动修订、不自动变成票 |
| 方案存在可复现的数据损坏缺陷 | 阻断受影响路径,保留证据与解除条件 |
| 具体误删风险无法在本地核实 | 重大风险待决,暂停相关任务;未知不记为通过 |
| 已确认决策与修复方案冲突 | 不自动覆盖用户决策;night 记录需要人决定 |
| 复审只剩新的一般建议 | 原阻断关闭后收敛,不重新开题 |
| 修复引入新的重大回归 | 允许新增阻断,不能因限定复审而忽略 |
| 同一发现换措辞/多个评审员重复提出 | 归并来源,不重复计数或重新打开已解决项 |
| grilling 中回答“选A”,稍后明确改为B | 快照绑定问题与选择,最终有效决策为B,保留变更来源 |
| 刚结束讨论但 docs 有无关新文件 | 审核当前讨论,不自动选无关文件 |
| CONTEXT/ADR 存在但没写完整 spec | 不把术语表当方案,不因未拆票而阻断 |
| 没装 Matt Pocock 讨论技能 | 显式文件或贴文照常可审核,night 内联流程不假依赖外部技能 |
| 仅无人值守审核 | 不实施、不推送、不创建PR |
| 完整 night | 文档与代码在同一夜链分支,原分支没有自动提交/推送/rebase |
| 某票有阻断且其他票依赖它 | 依赖票不执行,真正独立票可继续,部分完成不报全绿 |
| 无远端或 PR 权限失败 | 保留本地提交与晨报,如实记录发布未完成 |
| 只读配置或材料模式不能约束 CLI | 能力校验失败,不回退为全权访问真实工作区 |
| 升级分发模板/重复迁移 | 个人配置不丢失,不重复覆盖,有效配置与来源可查 |
| 不配通知或通知失败 | 正常交付会话结果与晨报,不阻塞 |
| 已完成票的提交不在恢复后的分支 | 不仅凭台账跳过;标记状态不一致,恢复证据或暂停 |

最后一项是本次核查发现的额外恢复风险:现行 worktree/分支缺失重建后依旧可能按旧台账跳票。建议把“台账完成项对应提交须可达”纳入本轮相关回归,不扩展成整个恢复框架重写。

度量建议:同一批共识样例上的阻断误报、重大缺陷漏报、无实质收益的修订轮数、未经确认的新增范围、用户需处理的决策量。暂不制定没有基线的数值提升承诺。

## 9. 后续工作分组与非目标

建议依次形成可独立验收的实施工作组,不是现在执行的任务票:

1. 共识快照、事实/阻断分离、归并标识和限定范围复审。
2. 共识约束传递、局部暂停依赖、仅无人值守审核入口。
3. 夜链同分支交付、发布结果拆分与恢复提交校验。
4. 配置分层、旧配置迁移、统一 setup/运行验证路径。
5. 各 CLI 的只读取证/材料隔离适配与能力测试;未经验证不启用新取证能力。
6. 场景回放、回归测试、用户文档及现行协议同步。

不做:自动合并PR、自动创建远端、安装登录各模型服务、团队权限管理系统、通用Webhook、多平台正式支持承诺、直接改造 Matt Pocock 上游技能。

实施时必须同步 SKILL、flow、intake、prompts、setup、配置解析、产物协议、CONTEXT、README、AGENTS、CHANGELOG 与测试。旧终态/机器账兼容规则和新旗标/字段需在实施规格中明确,不将旧记录按新词义直接重解释。

本次设计落盘不变更运行版本,不写“已实现”发布说明。相关边界决策见 docs/adr/0004-review-convergence-and-night-delivery-boundaries.md。
