## A. 凭据与交互面(封死泄露与弹窗)

- **脱敏先行(一切对外输出)**:任何 remote 串进晨报/账本/对话前先脱敏——剥 `scheme://[userinfo@]` 的 userinfo 段;结构识别失败 → 只印 host。compare 归一流程 = 脱敏 → 归一(`git@`/`ssh://` → https 形) → 拼 compare;归一失败兜底 = 印"脱敏 host + 分支名",**绝不印原串**。
- **交互面统一封堵(夜链子进程强制,不尊重原值)**:`GCM_INTERACTIVE=never`、`GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS=`(置空)、`SSH_ASKPASS=`(置空)、ssh 形态 `-c core.sshCommand="ssh -o BatchMode=yes"`。只影响子进程 env,不改操作者 shell 配置。`credential.helper` 保留不清空(rev1 决定维持)。
- **认证预检改良**:预检本身套用同一套非交互 env(防预检挂死);预检失败不再永久禁推——记 `publication_degraded`,首票完成推送时重试一次,再失败本夜停推记账。ls-remote 只验读权限:接受并注明(写路径失败本就逐票降级)。

## B. 恢复与清理(护栏在恢复场景仍成立)

- **每次 start 刷新底账**:含"幂等通过"分支——每次 start 重录 dirty baseline 并**重算停靠票**(崩溃→重启间操作者新改的文件立即进停靠判定)。
- **内容快照**:`git stash create`(不动工作区不进栈)生成悬空提交,`dirty_snapshot = <OID>` 存 NIGHT;仅作恢复兜底(`git checkout <OID> -- <path>` 找回内容),不自动应用、不修改工作区。
- **失败票路径清理(补 untracked)**:两步——①`git checkout <BASE> -- <票路径>`(BASE 存在的 tracked 文件;pathspec 无匹配时跳过此步);②`git clean -f -- <票路径>`(清 BASE 中不存在的新增文件;票路径与脏区不相交由停靠规则保证不误伤)。两步入账本。**越界残留连带清理**:失败清理时对该泳道越界清单内文件同样处置;后续票 commit 前与残留清单比对,命中即暂停提交报来源不明。
- **committed-未评审状态**:状态机补转移——`committed` 状态崩溃/恢复 → 恢复优先续做评审(输入=票 BASE..HEAD,账本可取);不可续 → `paused(committed-unreviewed,<OID>)`,提交保留不 revert,晨报列明。

## C. 链接与门禁(可执行化)

- **web_base 字段**:compare 链接的 host:port 不再从 remote URL 假设;NIGHT 增 `web_base`(默认=脱敏归一结果;内部 Gitea SSH/Web 端口不同时操作者一次性配置)。无 web_base → 按默认生成,晨报注明"链接若无效请设 web_base"。
- **门禁改可执行**:tag 硬门禁 = **单票平均 LLM 轮数 ≤20**(基线 38,口径沿用外部诊断文档的轮数统计);墙钟降为参考指标,分母改**意图执行票数**(complete+paused+rework 全计)、按实施段单独计,不作硬门禁。

## D. 提交安全(来源可证)

- **票路径夜链独占**:夜链启动播报声明"票路径文件夜链期间由夜链独占,清单见晨报";每票派发时对标注路径做**派发快照**(hash 入账本),commit 校验改为 `git diff <派发快照> -- <票路径>`,操作者中途手改同路径会在"快照→当前"差异中显形且无法归票 → 该票 `paused(来源不明改动)`。
- **路径两两不相交升格显式不变式**:就绪集校验对象 = 在跑票 **∪ paused 未清理票** 的路径。

### ① 查实的(实施时必须消化)

1. **共享 index 提交隔离**(高):泳道 agent 须被禁止 `git add`(只改文件);主会话按票提交用 `git commit --only <票路径>`,提交前拒绝既有 staged 条目。
2. **失败清理三步**(高):先 `git reset -- <票路径>`(清 index),再 `git checkout <BASE> -- <票路径>`(还原 tracked),再 `git clean -fd -- <票路径>`(删新增文件与目录);执行前先做"当前票路径差异仍可归票"确认,不可归票 → 暂停清理记 waiting。
3. **归因诚实性**(高):派发快照 diff 只是**文件级**部分覆盖,同文件内操作者手改与票改不可分——独占声明(夜链期间票路径归夜链)是主护栏,快照是辅助;文档不得声称全覆盖。
4. **路径互斥集合**(高):= 在跑票 ∪ paused 未清理 ∪ committed-unreviewed ∪ rework 全部占径状态。
5. **内容快照补全**(中):`git stash create` 的 OID 用 `git update-ref refs/xcheck/dirty-<ts> <OID>` 存正式引用防 gc;untracked 另做归档快照(或明示放弃并记录)。
6. **越界清单口径裁定**(中):以 rev1 全量 `git status` 比对为产生源,rev2·D 的票路径 diff 仅作归因辅助——两用并存,文档写明。
7. **material 判定规则**(中):来源为外部即 external,**无论键入/粘贴**;用户粘贴的外部贴文=external。
8. **路径规范化**(中):比较前统一 canonical(正斜杠、去 `./`、大小写按平台、目录包含语义=`dir/` 前缀;glob 与 rename 不支持,写明)。
9. **不变式改名**(低):"失败票路径 revert"→"失败票路径还原(reset+checkout+clean)"。
10. **门禁分母**(低):轮数分母=意图执行票数(complete+rework完成+paused+failed 全计,单票只计一次);另记一条端到端参考:夜链启动到晨报的总墙钟,窗口=一夜(≤10h)。
11. **预检判据**(低):`ls-remote` 判 exitcode 不判"有 ref"(空仓/pr_base 未推时 exit 0 输出空是正常)。
