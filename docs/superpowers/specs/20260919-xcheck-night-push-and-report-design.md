# 夜链自动推送 + 收尾三段式(0.18.0 设计稿)

日期:2026-09-19 · 状态:已定稿(两轮 grilling 12 问全落定 + renhua 审计 7 处修复并入) · ADR:[`docs/adr/0003-night-chain-auto-push.md`](../../adr/0003-night-chain-auto-push.md)

## 背景

0.17.0 夜链的安全栏"不 push、不开 PR、不合并"把夜链产出全部困在本机;收尾没有对话播报规范(模型自由发挥,输出看不懂);Pushover 通知跨项目认不出是哪个项目、哪个分支。2026-09-19 grilling 共识:推送政策反转 + 收尾输出三层统一骨架 + 通知可读化。

## 决策表

| # | 决策 | 结论 |
|---|---|---|
| D1 | 推送政策 | 反转铁律 9:默认必推;动机 = 备份 + 网页可看;失败不阻塞只通知 |
| D2 | 主分支语义 | 解读 A:主仓当前分支只收文档性提交(spec/票),收工直推;实施代码永远走 worktree 分支 + PR |
| D3 | 输出骨架 | 三层统一「夜链结论 → 简报 → 推荐下一步」;晨报保留四问,裁定清单压到文末附录;简报 = 晨报的对话层浓缩投影(不引入新交付物) |
| D4 | 夜链结论 | 四值枚举:全绿 / 带停靠完成 / 未完成 / 失败收工;短稿终态不记四值,记"未执行实施(<原因>)" |
| D5 | 推荐下一步 | 命令级、≤3 条、按优先级;第一条 = 当前最该做的单个动作;未完成变体第一条 = 续跑命令 |
| D6 | PR 工具 | gh(GitHub)→ tea(Gitea)→ 只推分支;幂等(先查已有);base = 主仓当前分支 |
| D7 | 失败边界 | push/PR 失败不阻塞、通知 + 晨报记账;主仓分支被拒 → pull --rebase 一次,再失败绝不 force;短稿终态无 commit 跳过推送 |
| D8 | 推送节奏 | worktree 建立即推(基线含 spec/票),每票完成即推(绿态竖切);PR 与主仓分支推送收工做 |
| D9 | 非主分支 | 主仓当前分支无论是否 main,收工一律直推;夜链实施分支永远 push + PR |
| D10 | ADR | 记 0003 |
| D11 | 通知身份 | title = `【<项目名>】<一句状态>`;项目名 = origin 仓库名 > 目录名;分支名不进正文、主题进正文;url 挂 PR;三节点 + 失败变体全统一;title 与正文中文都走 UTF-8 文件 |
| D12 | ID 纪律 | 裸 ID(分支名/PR 号/ts)禁令只管 Pushover 层;对话/晨报保留 PR 链接与 ts 路径(终端可点击、晨报要自包含) |

## 收尾输出骨架

对话三段式(夜链结论一行+数字+PR 链接 / 简报 ≤5 行 / 推荐下一步 1-3 条命令级)、通知(title+正文+url)、晨报(四问 + 文末「裁定与停靠附录」)——精确模板见 `xcheck/lib/flow.md` 第 11.7,此处不重复。
