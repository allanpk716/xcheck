# xcheck 评审闭环(/xcheck-close)+ 摄入强化 设计文档

> **文档性质**:两件事并成一个版本 v0.9.0(0.8.0 已被同日 carrier 后台化修复占用)——① 新增独立 skill `/xcheck-close`,把 /xcheck-review 产出的三类分级反馈**闭环处置**(逐条证实 → 执行实验 → 必改清单 → 修订方案 → 复审收敛);② 强化第 0 步摄入:方案型指代例外补确认关卡与事实提取、自包含输入零往返带背景。
> **日期**:2026-08-14(与 grilling 会话共识一致)

---

## 0. 一句话定位

`/xcheck-review` 现在止步于"三类分级 + 你拍板",用户看到分级后的"然后呢"没有答案。`/xcheck-close` 续上这条路:**机器先核实**(查证第 1 类、执行第 2 类实验),核实结果汇总成**必改清单**,据此**修订方案**(新文件,原稿不动),修订版可选**再评审**直到收敛。全程人在环:每个有成本/副作用的关口用户拍板。

---

## 1. 已敲定的设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 闭环形态 | **独立 skill `/xcheck-close`**,不进 flow.md 第 7 步 | 闭环要执行实验、动方案文件,与"只出意见"的评审性质不同;diag 模式下闭环大半不适用,内嵌会让 flow.md 按 mode 分叉 |
| 服务范围 | **v1 只支持 review**;diag 产物喂入 → 提示"diag 闭环暂不支持" | 诊断闭环(验证根因+修 bug)危险一个量级且形态不同,等真实需求再设计 |
| 事实层 vs 方案层 | **事实维持摘录铁律**(只摘原话不改写);方案允许固化改写 | 摘录可回溯、防 framing;方案讨论碎片必须固化才能自包含——两层各守各的性质 |
| 方案型指代例外 | **补两件事**:① 固化 proposal 用户过目确认后才 fan-out;② 固化同时摘讨论中用户陈述的事实填 `{{CONTEXT}}` | 现状是裸奔通道:改写无人把关 + 用户事实全丢;复用 0.3 确认精神 |
| 自包含输入 | **零往返静默带背景**:主会话扫最近对话摘相关用户原话填 `{{CONTEXT}}`,对话里明说一句(不弹窗);没摘到就不加 | 用户期望"触发后总会提取事实";自包含场景多一轮弹窗大概率是空扰,明说一句可见即可,用户不对劲可当场喊停 |
| 第 1 类查证执行者 | **主会话逐条查**(只读判据直接相关文件,不展开探索);>10 条才分批 subagent(subagent 回传证据、主会话裁决) | 查证是评判,按"subagent 只搬运"哲学归主会话;triage 判据已写明查哪,本该是小动作 |
| 第 2 类实验边界 | 允许:临时文件(放 `.xcheck/<ts>/exp/`,留底不删)+ 本地测试/benchmark/探测;**禁止**:改业务代码、联网外呼、部署 | "只设计不执行"在闭环内解禁,但副作用必须有硬边界 |
| 实验批准粒度 | **一次 multiSelect 批准要执行哪些条**(可全跳过);批过的不再逐条二次确认 | 人在环把住总关口,批后不啰嗦 |
| 修订执行者 | **主会话亲写**(它持有全量证据:各家反馈+查证结果+实验结果) | fan-out 出去要固化 prompt 丢上下文+自代入陷阱;让评审 agent 之一改方案=运动员兼裁判 |
| 修订产物 | **新文件** `<原名>.rev<m>.md`(原文件同目录)+ diff 呈现;原稿不动。原方案是固化文本(非文件)时 → 写 `.xcheck/<ts>/proposal.rev<m>.md` | 保留原稿对照,diff 本身是复审时"改了什么"的证据;铁律"不静默改用户文件"只破一半(新文件无中生有) |
| 复审触发 | **每轮问用户**要不要继续;硬上限 **2 轮修订** | 每轮复审=全量 fan-out,成本该用户定;第 2 轮还不收敛基本是方案根上有问题,继续循环是浪费 |
| 收敛判据 | 第 1+2 类问题清零(或只剩用户显式豁免的条目) | 可操作、可检验 |
| 复审 agent 集 | 取 `run.md` 的 SELECTED;缺员走 flow 分支 C 弹窗;close 支持 `--agents` 临时换集 | 同集复审才有可比性;换集是用户显式动作 |
| 闭环落盘 | 过程全写独立 `CLOSE.md`(阶段粒度追加);SUMMARY 只在闭环**全部结束时**追加一行 closed 标记 | SUMMARY 保持"那一次评审"的纯快照,过程膨胀进 CLOSE.md |
| 中断恢复 | 重跑 `/xcheck-close <ts>` 读 CLOSE.md,从未完成阶段续;**阶段粒度**,不逐条 checkpoint | 阶段内重做成本可接受,细粒度 checkpoint 复杂度不值 |
| run.md 元数据 | flow 第 4 步新增落盘 `run.md`(mode / SELECTED / ts / prompt 路径)——flow 的唯一侵入改动 | close 靠它定位复审集+判 mode;现状 SELECTED 不落盘,close 无从知晓 |

## 2. 总体数据流

```
/xcheck-review(现状,第 0~6 步)
  │  第4步新增:落 run.md(mode/SELECTED/ts/prompt路径)
  │  第6步收尾(review 模式)新增引导:"要闭环处置…→ 敲 /xcheck-close"
  ▼
SUMMARY.md(汇总 + 三类分级)
  ▼
/xcheck-close(新)
  定位 ts → 校验(run.md/SUMMARY/triage 段/closed 标记)
  ├─ 阶段1 · 查证第 1 类(只读,自动)──────────┐
  ├─ 阶段2 · 执行第 2 类实验(批准后)          │ 每阶段完成
  ├─ 阶段3 · 必改清单(汇总)                   │ 即追加写
  ├─ 阶段4 · 修订方案(批准后,主会话亲写)      │ CLOSE.md
  └─ 阶段5 · 复审(问用户,≤2 轮)              ┘
  ▼
CLOSE.md 完整 + SUMMARY 加 closed 标记(终态:收敛/推倒重来/无需修订/用户中止)
```

## 3. /xcheck-close 定位与前置校验

### 3.1 输入解析

- **无参数** → 扫 `<cwd>/.xcheck/` 取**最新 ts** 目录。
- **`/xcheck-close <ts>`** → 显式指定(`ts` 形如 `20260814-143012`)。
- **`--agents a,b,c`** → 复用三壳现成解析规则(一个空白分隔 token、纯逗号串、笔误报错停住),**只在复审轮生效**(临时换集)。

### 3.2 前置校验(任一不过 → 报错停住,不硬猜)

| 校验 | 不过的处理 |
|---|---|
| `<ts>` 目录存在且有 `SUMMARY.md` | 报"找不到该次评审",列出现有 ts 供挑 |
| `run.md` 存在 | 提示"旧版本评审产物,无 run.md;请重跑一次 /xcheck-review 再闭环" |
| `run.md` 的 `mode = review` | 提示"diag 闭环暂不支持" |
| SUMMARY 含 triage 三类分级段 | 提示"该评审无分级段(旧版产物),请重跑 /xcheck-review" |
| SUMMARY 末尾无 closed 标记 | 提示"已于 <时间> 闭环,终态 <X>";不重复闭环 |
| 已有 `CLOSE.md`(上次中断) | 进恢复模式:读已完成阶段,从未完成阶段续(见 §5.2) |

**closed 标记格式**(SUMMARY 末尾追加一行):

```
<!-- closed: 2026-08-14T18:32:00 · 终态: 收敛(1 轮修订) -->
```

## 4. 五阶段详述

### 阶段 1 · 查证第 1 类(只读,自动,不问)

- 对象:SUMMARY triage **第一类 · 可直接证实**的每条。
- **主会话逐条查**:只读该条"判据"直接指向的文件/配置/文档,不展开探索。条目 >10 条时可分批派 subagent(回传证据原文,主会话裁决)。
- 每条判三值:**✅ 证实**(反馈属实)/ **❌ 证伪**(反馈不成立)/ **❓ 查无实据**(判据指向处查不到,拿不准)。
- 纯读操作,不弹窗不批准。结果逐条写进 CLOSE.md(带证据一行:文件:行号 或 引文)。

### 阶段 2 · 执行第 2 类实验(AskUserQuestion 批准后)

- 对象:triage **第二类**条目(第 6 步已给出【验证目的/一句话方法/预期】)。
- **一次 multiSelect** 列出所有第 2 类条目让用户勾(可全跳过);批过的执行,不再逐条二次确认。
- 执行约束:
  - **允许**:写临时验证文件(一律放 `.xcheck/<ts>/exp/`,留底不删)+ 运行本地测试/benchmark/探测命令。
  - **禁止**:改业务代码、联网外呼、部署。
- 每条实验结果三值:**成立 / 不成立 / 无定论**(执行失败、超时、环境不满足 → 无定论,记录原因,不阻塞其他条)。

### 阶段 3 · 必改清单(汇总,呈现给用户)

| triage/查证结果 | 归宿 |
|---|---|
| 第 1 类 ✅ 证实 | **必改**(确认属实的问题) |
| 第 2 类实验 **成立** | **必改** |
| 第 1 类 ❌ 证伪 / 第 2 类 **不成立** | **不需采纳**(明确排除,免得反复纠结) |
| 第 1 类 ❓ 查无实据 / 实验 **无定论** / 用户跳过未执行的实验 | **未决**(呈现给用户逐条拍板:按必改处理 / 豁免 / 保持未决) |
| 第 3 类 存疑 | **仅参考**,不进清单主体(列出供查阅,带 ⚠️) |

- 必改清单为空 → 输出"无需修订",直接跳阶段 5(问要不要复审)或直接收尾。

### 阶段 4 · 修订方案(用户批准后,主会话亲写)

- 输入:必改清单 + 未决条目的用户处置。
- **主会话亲写**修订版,产出:
  - 原方案是**文件** → 原文件同目录写 `<原名>.rev<m>.md`(m = 修订轮次,从 1 起)。
  - 原方案是**固化文本**(prompt.txt 型)→ 写 `.xcheck/<ts>/proposal.rev<m>.md`。
  - 原稿**不动**;diff(原稿 vs 修订版)呈现给用户。
- 修订版正文遵守 flow 3.1 的**自代入陷阱**纪律:历史背景用中性陈述,不点名 agent、不写"异构评审"等触发词。
- 批准动作:呈现修订版 + diff 后问"采纳这份修订版进入复审?"(用户可要求再改)。

### 阶段 5 · 复审收敛(问用户,≤2 轮修订)

- 修订版落定后问:"要跑一轮复审吗?"——每轮都问,不自动接续。
- 复审 = 完整跑一遍 flow.md(mode=review):`{{PROPOSAL}}` = 修订版全文,新 ts 目录,照常落 run.md/prompt/summary/SUMMARY(含 triage)。
- 复审 agent 集:`run.md` 的 SELECTED ∩ 当前 INSTALLED;缺员走 flow 第 2 步**分支 C** 弹窗(用剩余集 / 重选);`--agents` 优先级最高。
- 复审结果回到**阶段 1** 对新一轮 triage 再闭环(CLOSE.md 记录新一轮 ts,形成链)。
- **硬上限 2 轮修订**;**收敛** = 最新一轮 triage 第 1+2 类问题清零(或只剩用户显式豁免条目)。
- 第 2 轮修订后仍不收敛 → 停止循环,报告"**建议推倒重来**:两轮修订后仍存在 N 个可验证问题,疑方案根基缺陷",终态记"推倒重来"。

### 收尾

闭环结束(收敛/推倒重来/无需修订/用户中止任一终态):

1. CLOSE.md 末尾写终态段(终态、修订轮次、产出文件清单)。
2. 给**最新一轮评审的 SUMMARY** 追加 closed 标记行(§3.2 格式)。
3. 向用户呈现闭环总结:必改了什么、修订版在哪、终态是什么。

## 5. CLOSE.md 与中断恢复

### 5.1 格式(阶段粒度追加)

```markdown
# CLOSE · <ts>
- 源评审:.xcheck/<ts>/SUMMARY.md(review,<N> 家)
- 复审链:<ts> → <ts2> → …

## 阶段1 · 查证(完成 2026-08-14 18:02)
- ✅ [codex] xxx —— 证据:src/foo.ts:42
- ❌ [kimi] xxx —— 证伪:y 文件实际是 z
- ❓ [opencode] xxx —— 判据指向处未查到

## 阶段2 · 实验(完成 …,批准 3/5 条)
- 成立 [codex] xxx —— exp/repro1.js,输出:…
- 不成立 [kimi] xxx —— …
- 无定论(跳过/失败原因)

## 阶段3 · 必改清单(完成 …)
…

## 阶段4 · 修订 rev1(完成 …)
产出:docs/spec.rev1.md

## 阶段5 · 复审(轮1 → ts 20260814-190500)
…

## 终态:收敛(1 轮修订)
```

### 5.2 恢复规则

重跑 `/xcheck-close <ts>`(无参时若最新 ts 已有 CLOSE.md 也算):读 CLOSE.md 已有阶段区块,**从未完成的阶段续跑,已完成的不重做**。粒度到阶段(如阶段 2 做到一半崩了,重跑整个阶段 2,不逐条 checkpoint)。阶段内的用户批准**不跨恢复记忆**——重进未完成阶段时该问的关口重新问。

## 6. 摄入强化(改 context-intake.md / flow.md 第 0 步)

### 6.1 方案型指代例外补强(0.0 例外路径)

现状走"主会话固化 proposal → 直接 fan-out",补两个动作:

1. **确认关卡**:固化出的自包含 proposal **呈现给用户过目**(复用 0.3 的确认形式:① 就这样,继续 / ② 我要改)。用户改后再确认一次。**过目通过前绝不 fan-out**。
2. **事实提取**:固化同时,把讨论中**用户陈述过的事实/约束**(用户原话摘录,不改动)单独摘出,填进 review 模板的 `{{CONTEXT}}` 槽,与 `{{PROPOSAL}}`(固化方案)分槽提交。事实清单同样在确认关卡里一并过目。

### 6.2 自包含输入零往返带背景(原"跳过摄入"路径)

- 判定自包含、准备直接用 `$ARGUMENTS` 时,主会话**静默扫最近对话**(~20 轮):摘出与方案直接相关的**用户原话**(约束、环境、已知现象),填 `{{CONTEXT}}`;对话里没有就不填、删槽行。
- **不弹窗、不阻塞**,但必须在对话里明说一句:

  > 已附带 N 条来自刚才对话的背景(未经逐条确认,若有出入请打断)。

- 摘录铁律不变:只摘原话不改写;`prompt.txt` 落盘留底(含 CONTEXT 段),事后可核查。

## 7. 边界与异常处理

| 异常情况 | 处理 |
|---|---|
| 最新 ts 是 diag 产物 / 无 run.md / 无 triage 段 / 已 closed | §3.2 各自的报错提示,**不硬猜不代跑** |
| triage 第 1+2 类全空(全 LGTM 或全第 3 类) | 阶段 1/2 输出"无",阶段 3 输出"无需修订",直接收尾(终态:无需修订) |
| 阶段 2 用户全跳过 | 正常,全部第 2 类条目归"未决",进阶段 3 |
| 实验执行失败/超时 | 该条记"无定论"+原因,不阻塞其他条 |
| 必改清单为空 | 跳过阶段 4,直接问阶段 5(要不要复审一轮确证) |
| 原方案文件在修订轮之间被用户手改 | 阶段 4 呈现 diff 时以原稿现状为基线;diff 对不上(原稿已变)→ 提示用户,以**当前文件**为修订基线,rev 序号顺延 |
| 复审轮 SELECTED 有 agent 已卸载 | flow 分支 C 弹窗(用剩余集 / 重选);`--agents` 直接盖过 |
| close 中途用户中止 | CLOSE.md 记"中止于阶段 N";SUMMARY **不加** closed 标记(下次可续) |
| 阶段崩了(工具错误等) | 同上——已落盘的阶段成果保得住,重跑从未完成阶段续 |
| `/xcheck-close` 对已在链中的复审轮 SUMMARY 再触发 | 正常闭环该轮(链式);closed 判定按该 SUMMARY 自身标记 |
