# 对象解析器:含糊输入靠上下文推断,确认窗做防错网

xcheck 此前的路由对命令文本做关键词匹配,输入一含糊("审核刚才的spec"、裸敲 `/xcheck`)就反问用户——但主会话明明握着全部对话历史,能看出刚讨论了什么、写过哪个文件。决定(v0.13.0):空/含糊输入设 `MODE = auto`,由 flow 第 0 步**对象解析器**按阶梯(文件型 > 讨论型 > 诊断型 > 反问)推断评审对象、模式与背景,**一个确认窗打包过目**后才 fan-out。旧的"不瞎猜就反问"原则不废除而是升级:猜(解析)可以,但结果必须过人确认才开跑——防错关口从"路由前"移到"开跑前"。

## Consequences

- "诊断还是评审"反问、指代词例外、方案型例外、普通摄入四套判定合并为一个解析器 + 一个确认窗;交互开口数不变(开头确认 + 结尾停点)。
- 文件型解析 source=路径,停点后的修订版落**原文件同目录**(`.rev<m>.md`),不再埋进 `.xcheck/`。
- 跨会话(新会话裸敲)看不到上一会话,兜底为扫惯用目录(docs/superpowers/{specs,plans}、docs/)取近 24h 最新;再无候选则反问。
