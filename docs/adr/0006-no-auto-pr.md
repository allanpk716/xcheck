# 不自动开 PR：交付止于已推分支 + 晨报一键链接

ADR 0003 决定收工自动开 PR（gh→tea 降级链）。rc.1 把它做成了显式目标助手 `night-pr.sh`：冻结 repo/base/head、查询复用开放 PR、查询失败不得转创建、fork 排除、URL 校验——46 行脚本 + 73 条测试，另带 GHES 端口、`pr list` 默认 30 条漏复用等适配边角。这些约束全部是为了"无人值守下把 PR 开对"服务的，而 PR 的消费者是早晨的操作者本人。决定(v0.22.0)：**夜链不自动开 PR**，收工只推夜链分支；晨报与通知附 compare 一键链接（`<remote 去掉 .git>/compare/<pr_base>...<branch>`，GitHub 与 Gitea 同式，纯字符串拼接，零登录零 API 零适配），开 PR 是早晨的一次点击。`night-pr.sh` 与其测试整体删除。推翻 ADR 0003 的"收工自动开 PR"一截；其"每票即推"一截保留（防全损），"主仓当前分支直推"一截已被 ADR 0005 推翻。

## Considered Options

- **保留 gh 自动创建、只删查询复用等复杂部**——仍有登录态/限流/托管差异三类失败要记账，换来的只是省一次点击，不值，否。
- **tea 路径做全**（Gitea 原生支持）——为第二托管再养一条降级链与它的边角，与精简方向相反，否。
- **连推送也省，纯本地收工**——退回 0.17 的全损风险，ADR 0003 的事故教训，否。

## Consequences

- 夜链的对外动作收缩为唯一一类：推夜链分支 ref（显式 URL、不 force）。
- 发布状态记账简化为：已推 / 未推（原因）；PR 字段删除。
- 远端早晨出现的是已推分支 + compare 链接，不是待处理 PR——评审入口从"PR 页"变为"一键开出来的 PR 页"，内容等价。
- 托管差异（GitHub/Gitea/其他）只剩 URL 拼接模式一处，不再需要工具降级链。
