# --night 验收协议:fixture 靶场+真实 CLI+七判据双条件通过;机械测试绿不等于验收

AGENTS.md 测试义务自认两条边界:「机械Git通过不证明全链行为已验收」、「静态检查不能证明模型正确理解,须区分已运行检查、场景回放和未授权未执行的真实CLI端到端」。五套机械测试(night-git / night-parallel / run-mode / review-contract / run-agent)只覆盖脚本层,真实 CLI 端到端从未执行;0.26.0 晨报新格式(一句话总判开头+文末对账区)也未实跑验证。经 grill-with-docs 确认验收协议如下。

决定(2026-09-29):

1. **靶场**:临时 fixture 仓库 + 本地 bare remote(严禁真推任何外部远端);评审 agent 用真实 CLI 至少两家(默认档与已装交集)。
2. **七判据**(全绿才算机制通过):①夜链零人工干预跑完 ②NIGHT 四阶段(review/plan/impl/finish)勾齐 ③票全 complete 或 paused 带原因 ④夜链分支推送成功且不 force ⑤晨报符合现行人话交付格式(一句话总判开头、正文零编号、文末对账区,体例见 CHANGELOG 0.26.0) ⑥每票有 scoped 验证记录 ⑦原分支零 commit/push。
3. **双条件通过**:七判据全绿 + 用户人工看过晨报点头,缺一不可——格式的人话程度只能人判。
4. **首验流程**:白天盯跑 fixture(只观察不干预;观察者出声干预即记为失败点,零干预判据照算),通过后再放一次真夜链过夜复验。
5. **重验触发**:凡动第 11 步、夜链行为、晨报/交付格式的版本,须重跑本协议;只动 prompt 文案与离线结构者,跑 review-contract 与相关套件即可。

## Consequences

- 验收通过记录落 CHANGELOG 对应版本条目;盯跑发现的失败点按票进 `.scratch/` 修复流程,不现场 hotfix。
- fixture 仓库模板(含 bare remote 初始化脚本)作为验收资产一次搭建反复用。
- 判据 ⑤ 与交付格式绑定,格式再改时判据同步改(同 AGENTS 文档同步义务)。
