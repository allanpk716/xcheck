# 并发帽直设并覆盖票级评审:night_parallel_lanes = 实施位+评审位,默认 3

ferryman 夜(2026-09-19,11 票全落地)实证:帽设 2 时操作者看到 4+ 子代理在跑——`night_parallel_lanes`(0.22,ADR 0007)只卡实施泳道,票级评审随提交即出发不占帽;而 429 集体阵亡的根因是**同时打上游的子代理总数**,不是同时写码的票数,原帽对不准真实风险。且该值此前只能手改 agents.toml。决定(v0.23.0):

1. **语义改为总并发帽**——`night_parallel_lanes` 罩"实施泳道 + 票级评审"的同时在跑合计数(冒烟、评审段 fan-out 不在帽内:后者并发=选集家数,`default_agents` 已是那一段的自然控制);空位补位**评审优先**(先解锁落地票、放行下游依赖,再派新实施,避免把 DAG 拧回串行);终局全分支 review 同占一位。
2. **双入口直设**,优先级 `--lanes > night_parallel_lanes`:`/xcheck-setup lanes N` 持久改配置;`/xcheck --night --lanes N` 单晚旗标(仅 `--night` 可携带,否则报错——评审段无泳道,防误期待)。整数 ≥1,`≥5` 警告不拦(429 前科)。
3. **默认 2→3**:ferryman 干净一夜后的手动升级,走的正是 ADR 0007 预留的"跑干净一夜后手动升"路径;出厂值与个人值不再区分。NIGHT 在 impl 开始记 `lanes = N(来源)`,续跑旗标改道只影响后续派发并追记一行。
4. **术语泛化**:泳道 = 夜链并发工作位,分实施位(只改文件严禁 git)与评审位(只读出报告);配置名不改。

## Considered Options

- **帽只卡实施泳道(维持 0.22 语义)**——帽数与总画面数脱节,N=4 时真实画面 5~6 个子代理,429 风险(总子代理数)对不准,否。
- **全局统一帽(连评审段 fan-out 一起卡)**——评审段并发=选集家数,再套帽是重复控制,且让 lanes 含义随流程阶段漂移,账本/晨报不好解释,否。
- **自动升降并发**——ADR 0007 已否(限流面前集体翻车,夜链翻车成本一整晚),本次维持:固定值、人工设,只把"设置"变直接。
- **配置改名 night_max_concurrency**——ADR 0007/测试/CHANGELOG/flow 全在用 lanes,纯改名是折腾;泛化定义即可覆盖新语义,否。

## Consequences

- 帽满时落地票的评审排队:票保持 committed、review 未过,**不新增台账状态**(committed-unreviewed 语义不变,仍特指"崩在评审前");评审晚几拍出发,但提交本就在主会话串行,影响小。
- 评审优先补位最大化 DAG 解锁速度;实施派发相应让位。
- `--lanes` 不带 `--night` 报错停住;`--auto-review` 携带同样报错。
- 账本/晨报可解释"今晚 N 道并发",排障有锚点;`night-parallel.test.sh` 契约断言同步(默认 3、帽罩评审、评审优先、旗标规则)。
