# 实施调度：事件驱动就绪集，编辑并行、提交串行

外部速度诊断（ferryman 主线 16.1h）：96.5% 时间只有 1 个子代理在跑，`实施票 N → 评审票 N → 实施票 N+1` 串行链让 12.5h 纯 LLM 时间无法摊薄；上游 Matt 技能的 to-tickets 数据模型本就并行就绪（阻塞边），但 `implement`/`wayfinder` 均为单线程设计，从未有人把 DAG 真正并行跑起来。决定(v0.22.0)：**事件驱动就绪集调度**——任一票落地（完成或停靠）触发协调者重算就绪集并立即补位派出；就绪 = 依赖已满足 ∧ 涉及路径与在跑票不相交 ∧ 泳道有空位；逐票评审随该票提交即出发，不等全队。**泳道 agent 只改文件、跑票内局部验证，不 commit；主会话逐票验收后按票提交（显式路径）再推送**——编辑并行消除 LLM 串行等待，提交串行消除 git 索引竞态。恢复语义：票账本（complete/paused/blocked + 依赖边 + 涉及路径）即检查点，续跑 = 重算就绪集。泳道数 `night_parallel_lanes` 默认 2，跑干净一夜后手动升——2026-09-19 当日 10 个并行子代理打 GLM 触发 429 集体阵亡是上限必须实测的直接证据。落者超时/失败记 paused，不拖队。

## Considered Options

- **波次屏障调度**（按依赖层整波推进）——实现最简，但快票的评审要干等慢票的实现，流水线退化为批处理；且票账本本身就是逐票状态机，波边界并不提供额外恢复能力，否。
- **动态就绪集 + 自动升降泳道数**——自动升道在限流面前会集体翻车，夜链翻车成本是一整晚（小时级）不是几分钟，否；固定配置、人工升。
- **每泳道独立 worktree/克隆再合并**——并行编辑的另一种隔离法，但与 ADR 0005"技能不管隔离"冲突，且合并冲突处理是新的复杂度中心；路径不相交约束下单检出已够用，否。
- **保持串行，只砍长尾**——诊断算术：并行度 2–4 直接摊薄 60–78% 的 LLM 墙钟，是最大单项杠杆，串行砍长尾空间有限，否。

## Consequences

- to-tickets 产出增"涉及路径"标注，一份数据两用：调度不重叠判断 + 派单包内联文件清单（目标单票 38 轮 → ≤20 轮）。
- 并行编辑期间工作区同时存在多票未提交改动；权威验证在提交时逐票做（scoped），终局一次全量套件——局部验证给泳道自信，不作为完成依据。
- 路径重叠的票自动串行（排在后续就绪集），跨票集成回归风险由"终审最强档全分支 review"兜底。
- 派单模板前缀必须稳定（保前缀缓存命中），模板改动即缓存失效，改模板要谨慎。
