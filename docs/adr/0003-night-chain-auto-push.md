# 夜链自动推送与自动 PR:从"纯本地收工"到"进度必上远端"

0.17.0 的夜链安全栏规定"不 push、不开 PR、不合并",终点 = 本地分支 + 晨报——夜里一切对外动作全禁。实际跑下来暴露了反面的风险:夜链一跑数小时,产出(实施分支、spec、票)全部困在本机,机器故障或误删 worktree 即全损。决定(v0.18.0):**推送政策反转**——每票完成即推夜链分支,收工自动开 PR(base = 主仓当前分支),主仓当前分支的 spec/票提交收工直推;"不管怎么样都要推送"成为默认,推送失败降级为通知 + 晨报记账,不挂链。同时收尾输出统一「夜链结论 → 简报 → 推荐下一步」三层骨架,通知加【项目名】title 与 PR 链接。

## Considered Options

- **保持纯本地,早上人工推**——进度保全取决于人是否记得;夜里机器出事即全损,否。
- **只 push 分支,不开 PR**——进度保住了,但远端一堆裸分支不可读,网页上看不到整体 diff 与停靠清单,否。
- **推送 + 自动合并**——把"合并"这个唯一留给早上的决策也自动化了,越权,否。

## Consequences

- 铁律 9 的对外禁令改为**白名单**:每票推送、收工开 PR、主仓当前分支直推三类之外仍全禁(绝不 force push、不自动合并、不上 issue tracker、不动主工作区)。
- 远端夜里会出现多次更新的 WIP 分支与一个待处理的 PR——接受的代价:每票都是测试全绿的竖切,推上去的不是半成品。
- 主仓当前分支推送被拒(非 fast-forward)时:`git pull --rebase` 一次重试,再失败绝不 force,通知人工。
- PR 工具按远端降级:GitHub(gh)→ Gitea(tea)→ 只推分支;任何失败不阻塞。
- 收尾三层输出(对话三段式播报 / Pushover 通知【项目名】+PR 链接 / 晨报四问 + 文末裁定附录)共用「夜链结论」四值枚举(全绿 / 带停靠完成 / 未完成 / 失败收工)。
