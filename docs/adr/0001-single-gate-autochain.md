# 单停点全自动链:xcheck 从"每关都问"改为"一处拍板"

xcheck 此前把"人在环"实现为流程中每个有成本/副作用的关口都停下来问用户(选 agent、批实验、逐条拍板未决、采纳修订、要不要复审),而 /xcheck 与 /xcheck-close 两次触发把一次评审撕成两半——实际使用中这些关卡几乎总是直接通过,成了仪式性交互(2026-09-16 grilling 共识)。决定(v0.12.0):**合并为单一自动链**——`/xcheck` 一次触发,自动跑完盲评 → 三分类 → 查证① → 实验②,只在终点呈现**已验证三分类清单**处停一次(单停点),问"要不要起草修订并自动复审"。人的控制权从"过程每步签字"移到"对最终结果拍板";真正不可逆的动作依然不存在——修订永远写新文件、原稿不动、实验永远在沙箱内(禁改业务代码/禁联网/禁部署)。命令面 5 → 2(/xcheck、/xcheck-setup)。

## Considered Options

- **关口全保留、只自动衔接两命令**——治标不治本,交互次数不变,否。
- **零关口全自动(连采纳都自动)**——丢掉唯一真正值得人拍的决策,否。
- **内容指纹自动续跑(同输入即续)**——不可推理、调试负担,否;改为**自动发现未完成链 + 人工确认"续还是新开"**(机器发现、人决定,与停点同一原则)。

## Consequences

- ②类实验改为自动执行;安全性完全托付给沙箱铁律(临时文件落 `.xcheck/<ts>/exp/`、禁改业务代码、禁联网、禁部署),单条超时判"无定论",不设总预算。
- close-flow.md 与 xcheck-diag / xcheck-review / xcheck-close 三个薄壳删除;/xcheck-close 不复存在。
- 进度只认盘:每阶段完成即写 `PROGRESS.md`(阶段粒度);旧版产物(有 run.md 无 PROGRESS.md)视为不可续跑的已完成运行。
- diag 模式维持现状(止步于汇总+三分类),不进自动链、不做 diag 闭环。
