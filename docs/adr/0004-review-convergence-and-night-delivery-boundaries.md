# 审核围绕阻断收敛,夜链产出统一经分支交付

2026-09-19 的 grilling 访谈确认:审核对象主要是讨论共识,小问题持续扩张是当前主要痛点。决定将事实成立与是否阻断分开,按核心目标、验收、安全、数据正确性与实施前置条件裁定;复审以修复验证和回归为中心,非阻断建议不自动扩大实施范围。用户已确认的产品行为与约束不能被夜链擅自改定。

保留 `--night` 默认实施到 PR 及命令本身的授权语义,同时将无人值守与执行终点分开表达。spec、任务票和代码统一在夜链分支交付,不再自动提交或推送启动原分支;无法发布时保留本地成果并明确披露,不自动合并。

**状态说明**:第一至三批已实现相关审核/模式/隔离交付流程,实际外部CLI与真实托管发布仍待端到端验证。本记录现替代 ADR 0003 中“spec/票先在原分支提交、收工直推原分支及拒绝后自动 rebase”的部分;ADR 0003 的进度推送、PR 不自动合并与失败记账动机仍保留。

## 取舍

- 不采用“所有属实建议都必须修订”:它看似严格,却让格式细化和偏好建议不断延长审核,还会将未授权建议转为需求。
- 不采用“复审不允许任何新问题”:限定范围不能成为忽略重大回归的理由。
- 不将 night 改成默认只审核:用户已有完整夜链使用习惯,保留兼容入口,另提供仅无人值守审核。
- 不保留原分支文档直推:统一 PR 增加了隔离与恢复设计工作,但使所有拟合入产出可一起审查,不再让“代码隔离”掩盖对原分支的修改。

## 后果

问题标识、裁定记录、状态、依赖暂停与旧账本兼容需要一起设计;不能仅替换提示词中的“必改”二字。夜链须在规格和任务票生成前建立隔离工作区,恢复须核实完成项对应提交仍存在。设计详见 [审核收敛与可分发配置](../superpowers/specs/2026-09-19-xcheck-review-convergence-and-portability-design.md)。
