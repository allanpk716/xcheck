# review_schema = 2 · 审核契约

仅适用于 review。主会话在摄入、分类和交付前读取本文;diag 保持旧三分类与诊断终态。步骤编号与 PROGRESS 的11阶段不变。

## 对象与共识

审核目标是关键决策足以支撑实施,不是要求讨论共识已经包含全部文件清单、任务票与测试步骤。用户显式指定的文件/贴文是对象;显式“刚才讨论”优先当前讨论,CONTEXT/ADR和近期文件只能作为相关背景。

`proposal.md` 固定本轮对象;`context.md` 保留必要背景原话;每个review必建 `decisions.md`:

```markdown
# 决策快照
review_schema = 2

## 目标与范围
<目标、验收预期、明确不做什么;缺失如实标记>

## D1 · <决策主题>
状态: 已确认 | 未决 | 否决 | 假设 | 已替代
内容: <完整决策,不只写“选A”>
来源: <文件:节/行,或问题原文+选项原文+用户回答片段>
替代: 无 | D编号
影响范围: <相关行为/目标,或待确定>
```

D编号在链内稳定;后续明确修正产生新记录,旧项标已替代。用户短答须与对应问题/选项绑定;文件中的明确要求注明“来自用户指定材料”,不能虚构为会话逐项确认。助手未获确认的建议只能是假设或未决。上下文不可见/出处缺失就写明,不得伪造引文、消息编号或默许同意。没有可摘录决策也要建文件说明覆盖限制。

主会话自动整理快照,不要求用户重审全文。只在对象或重要决策存在歧义时正常模式确认;夜链记录未决并暂停受影响路径,全局目标不明则停止。已有明确用户决定与事实冲突时可以指出问题,但不得自动替换产品行为/约束。

## 发现身份与记录

第6步 review 使用 `triage-review.md`,将所有反馈映射到 `FINDINGS.md`;原始 `.summary.md`/`.raw.out` 保留不改。每条原始反馈必须映射到一个F编号,多来源同一故障可归并,不同发生条件/后果不能误合并。①②③均有编号,编号不因类别/排序/严重度变化而改变。

```markdown
# 审核问题记录
review_schema = 2

## F1 · <主张>
来源: <agent:条目位置; 可多个,保留各家的严重度/类型>
关联决策: D1 | 无(说明与目标关系)
发生条件: <具体输入/情境>
取证分类: ① | ② | ③
事实: 待验证 | 证实 | 证伪 | 未确定
证据: <引文/文件:行/实验产物,没有则写缺什么>
影响: <目标/验收/安全/数据/前置条件的具体后果>
裁定: 待裁定 | 阻断 | 非阻断建议 | 重大风险待决 | 无需动作
范围: <受影响行为/任务; 未确定不能写成无影响>
解除条件: <可核验的条件,或无需解除>
决策冲突: 无 | D编号及需要用户决定什么
生命周期: 开放 | 已解除
历史: <本轮新增/归并来源/修复及证据/重新开启理由>

## 来源映射
- <agent:条目位置> → F1
```

空反馈写“本轮无反馈”,仍保留头部和来源映射空说明。复审从上一环复制完整问题记录再更新,不得将本轮没再提到的问题自动关闭或丢弃。新增问题递增编号;重开已解除问题必须附新证据或具体回归。收集/分类重跑须幂等,先读已有映射,不能重复发新编号。

对 `decisions.md` 的未决/冲突逐项检查:影响目标、安全、数据或实施前置条件的实际缺口也必须有F记录,来源写 `摄入:D编号` 或 `主会话查证:<证据>`;不得冒充外部评审意见。纯粹缺失细化步骤不自动变成缺陷。

## 分类、验证与裁定

取证分类只回答怎么核实:①只读可核实,②需本地实验,③当前无法验证。严重度是来源标签,不是阻断开关。第7/8步分别把核实结果写回F记录;①查无实据、②无定论、③一律事实=未确定,不能当证伪或通过。

第9步在任何早退/终态之前,主会话对全部F记录裁定。已解除的历史问题先核新方案仍满足解除条件,证据仍有效就保持已解除;原缺陷当时属实不等于当前仍阻断。修复有效但原主张历史上属实时,历史事实保留,当前生命周期仍可已解除;重开必须新证据。对当前尚未解除的问题按顺序:

1. 证伪 → 无需动作,已解除,保留反证。
2. 证实且影响核心目标/验收、安全、数据正确性或实施前置条件 → 阻断,开放,必须写范围与解除条件。
3. 未确定但有具体严重后果场景或缺少关键用户决策,不能排除影响 → 重大风险待决,开放,写缺失证据/决策及解除条件。不能因为①②为空跳过③。
4. 不达到阻断或重大待决门槛的完善/偏好 → 非阻断建议,开放但不强迫实施;无可行动问题 → 无需动作,已解除。

“更健壮/最好加上/不够详细”本身不是影响证据。未确定的泛泛担忧不以风险名义阻断。已确认约束与修复冲突必须显式记决策冲突,自动修订不能改定它。证明假设错误不等于获得改变需求的授权。

**活动约束 = 生命周期为开放且裁定为阻断或重大风险待决的记录**。只有活动约束为空才整体可推进。无下游依赖、允许用户收工、先停靠或修订预算耗尽均不解除约束。

**计算前校验**:每条F的全部必需字段须存在,取证分类/事实/裁定/生命周期须为合法枚举;缺字段、未知枚举、状态相互矛盾或来源映射缺条,先据现有证据补正,不能确定则停止交付通过并报告记录不一致。缺生命周期/裁定不能被过滤成“零约束”。范围未知必须显式写待确定,不能视为无影响;无证据不能填证实。已解除须有解除或证伪依据,否则不得凭空关闭。

## SUMMARY、附录与终态

裁定先写FINDINGS,然后 SUMMARY 机械投影五字段:状态(可推进/相关路径暂停)、活动约束(问题、证据或缺口、范围、解除条件)、各家裁决、信号、统计(取证结果及活动约束计数)。附录/对话另可精选收益明确且范围相关的非阻断建议,无需凑数,不把全部原始反馈平铺给用户。

必需的决策与证据不能只有机器编号:对话要当场说明问题、为何影响、暂停哪里、如何解除、当前需要用户决定什么。所有原始反馈可在机器账追溯,一般建议不自动成为规格或票。

七个终态标签保留,review_schema=2 时含义为:

- 无需修订:round 0活动约束空;可以有非阻断建议。
- 收敛(N轮修订):修订后活动约束空;不是所有建议清零或测试全通过。
- 用户不修:用户选择先交付,活动约束仍保留,不等于允许下游绕过。
- 夜间收工:兼容保留的无人值守预算/决策边界交付标签,auto-review与night均可使用;不记成人的决定,不等于已放行,更不是实施权限。
- 推倒重来:仅用户明确选择放弃;用户中止:用户中止;完成(diag):沿用diag语义。

## 限定范围复审

`re-review.md` 只评原约束修复、修改引入的回归和新发现的重大缺陷。`re-review-context.md` 内容层必须带上上一环全部F记录、D快照、修订差异和每条修复理由;不得向某家提供本轮其他家的反馈。

原阻断未再出现不代表解决,要查证解除条件。普通新增建议留底,不触发再修。无人值守(--auto-review及--night)最多一次自动修订,只有存在可在已确认范围内修复的阻断才动笔;仅重大待决、需要变更用户决定或无可执行修复时直接交付夜间收工。无进展=没有原活动约束经新证据解除且无新的可验证解决路径,不是字数变多/问题改名/降严重度。手动用户可以选择再修,但无新方案时要如实说明,不得假装有进展。

修订基于本轮快照。原文件变化不能自动改用新内容续审:正常模式把对象歧义交用户,无人值守暂停相关修订,保留原快照和差异。

## 下游约束

规格输入绑定最新已核验环的proposal快照及同环D/F,不得扫描最大rev或使用审核后变化的source替代;快照/账本缺失不允许接续。规格只继承已确认共识、必要修复和验收目标。非阻断建议未被用户明确采纳前不得新增故事/票。所有活动约束须映射到受影响行为与票,票记 `review_blocks: F编号或无` 与依赖票。

可执行票 = 自身无活动约束且所有依赖票已验证complete。直接约束票记 `paused(F编号,解除条件)`,依赖未完成的票记 `blocked(票编号)`,无法证明独立的票也暂停;不是全部整链停,也不能猜测独立。已暂停不自动重试;仅有解除证据/新决策才重新计算状态。

实施评审同样按具体影响裁定,不将全部Minor自动扩为任务。真实阻断不能因“无下游依赖”或达到修复上限停靠后视为已完成。终局只修相关重大问题与回归,一般建议记账不扩范围。有paused/blocked或活动约束残留不得报全绿;全部都暂停时不写代码,仍交付原因与解锁条件。

## 版本与恢复

- 新review的PROGRESS及NIGHT均写 `review_schema = 2`;diag不写且不走本契约。新复审环携带同schema与完整D/F记录。
- 无schema的旧review已结束:只读展示旧语义。未结束:保留原目录,新建schema2环 `migrated_from=<旧ts>`,从可取得的对象/背景重新审核,round=0、prev=-,不继承旧通过/验证结论。源内容不可取得就停止说明。
- 迁移不重置无人值守预算:新根环记 `auto_revisions_used = <已用次数|unknown>`,依据旧round/修订链可核实记录计算;旧round≥1则至少已用1次,无法核实记unknown并禁止自动再修。新原生首环为0,每次自动修订建子环递增并继承;无人值守修订仅已用次数明确为0才允许。
- 迁移幂等:先找 `migrated_from` 对应的新环,存在则续新环,不得反复新建。旧目录不改为“完成”;壳扫描将已有迁移目标的旧目录转向目标链最新环。
- 旧NIGHT存在且plan有产物或impl已开始:不自动迁移执行、不重放旧原分支推送;报告旧账本/分支位置,暂停等专门恢复处理。已结束旧链仍可阅读。
- 未知schema拒绝执行。schema2摄入完成必须有proposal/decisions,triage完成须有FINDINGS;复审还须有re-review-context及上一环映射。必要产物缺失就报告状态不一致,不能仅凭勾选跳过。
- 票complete必须有当前分支可达的提交和验证记录。worktree/分支丢失或提交不可达,停止该实施恢复,不从spec重建后跳过旧完成票。

## 交互方式与执行终点

新PROGRESS写interaction/target,复审和迁移原样继承。三种有效组合:interactive/review(正常审核)、unattended/review(--auto-review)、unattended/implementation(--night)。未提供模式旗标的续跑按账本恢复,显式旗标与账本不符就停止,不悄悄升级或降级。

`lib/run-mode.sh`是模式规范化的唯一机械入口:新链传request,续跑传request及三项旧字段(interaction,target,night),缺失用`-`;只允许两新字段同时缺失的兼容映射(night=on→完整night,无night→正常审核)。半缺、非法值或与night标记矛盾拒绝。它只解析模式,不验证schema或授予执行权限。

INTERACTION决定摄入/停点是否问人,TARGET决定是否接续实施。TARGET=review不创建NIGHT、不运行第11步、不通知/推送/开PR,但保留审核所需本地快照、修订稿与附录写入。仅INTERACTION=unattended且TARGET=implementation能创建NIGHT;NIGHT存在但目标为review须报告状态冲突。diag始终不实施,也不能靠target把诊断变开发。

## 隔离交付边界

完整night按 `lib/night-delivery.md` 执行delivery_schema=1。审核共识/修订/附录仅写原仓.xcheck,original_source只追溯,不追加原稿;普通审核/auto-review保留原附录行为。摄入冻结host_repo/start_oid/source_branch/remote_name/remote_url/pr_base,复审原样继承;旧运行无基线不从当前HEAD猜回启动时点。

spec/票生成之前先prepare隔离worktree,以后全部提交只在该worktree,原分支不commit/push/pull/rebase。发布只推夜链分支,PR明确冻结仓库/base/head,不可为开PR推送base。无远端仅本地执行,发布状态独立记账。恢复须verify所有已完成票完整提交OID及验证证据,路径/分支/提交缺失暂停;旧night有产物缺delivery_schema元数据拒绝自动恢复,不能绕过新版边界。
