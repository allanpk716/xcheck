# xcheck 上下文摄入(flow.md 第 0 步,可选)

主会话(你)在进 flow.md 第 1 步之前执行这一步。**目的**:xcheck fan-out 出去的 agent 是全新进程、看不到我们的对话历史;当用户用指代性输入(如"诊断刚才那个")触发时,自动把最近对话里的**客观事实层**摘出来,经用户逐条确认后,作为 fan-out 的输入内容。

`$ARGUMENTS` = 用户触发命令时给的文字。mode 由入口 skill 指定(diag / review)。

---

## 第 0.0 步:触发判定 —— 摘还是不摘?

判断 `$ARGUMENTS` 是否**自包含**(已是完整问题 / 方案,不需要对话背景):

- **自包含 → 跳过摄入**,直接用 `$ARGUMENTS` 进 flow.md 第 1 步(现行行为不变)。自包含信号:完整报错栈 / 异常堆栈、设计文档全文、大段代码块、文件路径、明显足够长的完整问题描述。
- **不自包含 → 运行摄入**。不自包含信号:`$ARGUMENTS` 为空、很短(不到一句话)、或含指代词(刚才·那个·上面·之前·这个·刚才说的 / this·that·above·prior·earlier·just now)。

> 拿不准就**倾向于运行摄入** —— 摘录 subagent 很便宜(haiku),多摘一次的代价远小于把没头没尾的问题喂给 N 个 agent。

## 第 0.1 步:建时间戳目录 + 切对话

1. 生成本地时间戳目录 `<cwd>/.xcheck/<YYYYMMDD-HHMMSS>/`(例 `20260809-143012`)。**后续 flow.md 第 1–5 步复用这个 `<ts>`**(原第 3.2 步的建目录动作移到这里,别重复建)。
2. 取**最近对话**(默认整段;极长则截最近 ~20 轮,保留用户最新的陈述),写进:
   ```
   <cwd>/.xcheck/<ts>/dialog-snippet.txt   # 绝对路径
   ```
   片段里要保留"谁说的"(用户 vs assistant)的可区分标记,方便摘录员按来源筛。

## 第 0.2 步:派摘录 subagent(一条 Agent 调用,haiku)

用 **Agent 工具**派**一个** subagent,模型用**便宜档(haiku)**。指令 = `~/.claude/skills/xcheck/lib/extractor-carrier.md` 的**全文**,末尾追加:

```
DIALOG_FILE = <cwd>/.xcheck/<ts>/dialog-snippet.txt
```

等它返回事实清单(一段 `## 摘录事实清单`)。

- **铁律**:摘录 subagent 只摘录、不改写、不评判(见 extractor-carrier.md)。它只干这一件事。
- 若它返回"未摘到用户事实",说明对话里没有可用背景 → 跳到第 0.4 步(退回反问用户)。

## 第 0.3 步:逐条确认(AskUserQuestion)

把摘录清单呈现给用户,**逐条确认**(不是看一段总结点头)。用 AskUserQuestion,问题文本大致:

> 我把刚才对话里的客观事实摘成了下面这些(已剔除我自己的推理 / 猜测,只留你说过的和贴过的)。**逐条核对**:有错的、要删的、还要补的,告诉我。
>
> 【清单】
> [用户] …
> [材料] …
>
> ① 就这些,继续 / ② 我要改(在"其他"里说明)

- 用户确认 → 用确认后的清单进第 0.5 步填槽。
- 用户要改 → 按其说明增删改后,再确认一次(或直接采纳其改后版),进第 0.5 步。

> **为什么必须确认**:摘录"算不算用户事实"仍是判断,会错;逐条核对能让用户在 fan-out 前把住关。一次 xcheck 是 N 家的 token + 时间,跑错返工贵得多 —— 这一眼几乎不费用户什么,经济上绝对值。

## 第 0.4 步:退回反问(无可用背景时)

若第 0.2 步摘不到任何用户事实,或对话根本没相关内容(如本次命令是会话第一条消息):**别硬编**,用 AskUserQuestion 直接问:

> 没在最近对话里找到可用的背景。请把要诊断 / 评审的问题或方案贴一下(或给文件路径)。

拿到用户输入后,把它当作 `$ARGUMENTS` 进 flow.md 第 1 步(此时已自包含,无需再摄入)。

## 第 0.5 步:填槽,交给 flow.md 第 1 步

把**确认后的事实清单**作为本次 fan-out 的输入内容:

- **mode=diag** → flow.md 第 3 步填 `{{USER_INPUT}}` = [用户原始 `$ARGUMENTS` 中含实质内容的首段,若有] + 确认后的事实清单;`{{CONTEXT}}` 留空或删行(背景已并入 USER_INPUT)。
- **mode=review** → flow.md 第 3 步填 `{{PROPOSAL}}` = [用户原始 `$ARGUMENTS` 中含实质内容的首段,若有] + 确认后的事实清单。

然后**正常进 flow.md 第 1 步**(检测 agent → 多选 → 并行派 → 收齐 → 汇总),后续不变。

---

## 边界(铁律)

- **摘录 ≠ 总结**:绝不改写原文措辞 —— 这是可检验、可回溯的底线;一改写就变回不可检验的总结,framing 风险回来了。
- **按来源筛,不按事实性筛**:留用户说的 / 贴的,丢 assistant 推理。
- **不自动跳过确认**:护栏必须保留。
- **自包含输入跳过摄入**:别给本来就很完整的问题多加一次往返。
